# 스키마 트랙 완료 기준 — 2026-08-19

> 착수 전에 **합격선과 안 할 것을 숫자로 못박는다.** 이 프로젝트 합의 방식이다.
> 근거는 전부 실측이며 위치를 적었다. 추정치에는 그렇다고 표시했다.

---

## 1. 목표 — 왜 스키마 트랙이 종착점인가

2026-08-19 농협 협의 결과, 트랙이 둘로 갈렸다.

| 트랙 | 대상 | KL(Knowledge Lake) 적재 | 최종 산출물 |
|---|---|---|---|
| 규정문서 | 법령·심의사례·은행연합회 준수사항 | **한다** (`_hrc.jsonl` 규격) | KL 인덱스 |
| **광고물** | PDF·PNG·HWP 광고 | **안 한다** | **스키마 추출 결과** |

광고물은 KL에 넣지 않고, 우리가 뽑은 스키마 추출 결과를 **질의어로 삼아** KL 벡터DB와
RDB를 조회해 심의 결과를 만든다. 즉 **광고물 트랙의 끝이 스키마 추출 결과**이고,
그래서 이 트랙이 프로토타입의 종착점이다.

## 3. 완료 기준 — 숫자

### 3-1. 결정론 층 (단일 수치로 제시해도 되는 것)

| # | 지표 | 합격선 | 근거 |
|---|---|---|---|
| D1 | `input_gap_regions` | **0** | 파싱은 됐는데 STAGE_3 입력에서 빠진 영역 = **우리 결함**. 2026-07-28 에 33→0 달성한 이력이 있다 |
| D2 | `absence_needs_check` | **0** (예금성) | 세부유형을 못 정하면 부재 판정이 통째로 보류된다 |
| D3 | 재실행 결정론 | `VLM_CACHE=p` 재실행 시 **산출물 해시 동일** | 실측 231초→4.7초, 해시 동일 |
| D4 | 스키마 로드 | 예금성 **62필드/9그룹**, 대출성 **69필드/10그룹** | 이미 통과 |
| D5 | 계약 검증 | `ExtractResult.model_validate` 통과, `errors` 빈 배열 | 그룹 전체 실패가 있으면 여기 남는다 |

### 3-2. VLM 층 (범위로만 제시할 것)

| # | 지표 | 합격선 | 근거 |
|---|---|---|---|
| V1 | 예금성 필드 회수 | **≥42/44 (95%)** | v1 기록 41~43/44(4회 관측 42·43·42·41), 이후 44/44. **v2 는 프롬프트를 전면 재작성했으므로 새 baseline** |
| V2 | 대출성 필드 회수 | **≥6/7 (86%)** | 골드 7개 값과 `must_contain` 9줄이 **전부 `llm_view` 안에 실재함을 확인**(7/7, 9/9). 즉 파싱은 다 건졌고, 미달이 나오면 원인이 **추출 단계로 특정된다** |
| V3 | `evidence_unbacked_count` | 관측만 | 근거 환각 의심 신호. 판정 기준으로 쓰지 않는다 |
| V4 | `region_coverage` | 관측만 | 문서마다 크게 다르다(실측 001 0.50 / 002 0.911 / 올원e 0.791) |

### 3-3. absence 3분류를 판정에 어떻게 쓰나

| 분류 | 판정에 쓰나 | 이유 |
|---|---|---|
| `해당없음` | **아니오** — 관측만 | 상품유형상 성립하지 않는 항목. 많다고 나쁜 게 아니다 |
| `미표시` | **아니오** — 관측만 | 광고에 표시 의무 항목이 안 보인다는 **사실**이지 위반 판정이 아니다. 정답(준법팀 확인)이 없으므로 정확도를 잴 수 없다 |
| `확인필요` | **예 — 0이어야 한다** (D2) | 우리가 유형을 못 정했다는 뜻. 우리 쪽 문제다 |
| `판정제외` | 아니오 | 분류·수집·관측·절차 등급 |

**핵심**: `미표시` 건수를 성능 지표로 쓰지 않는다. 광고마다 정당하게 다르고, 정답이 없다.

## 4. 안 할 것 (명시)

| 안 하는 것 | 왜 |
|---|---|
| 카드 스키마 신설 | 이번 범위 밖. 카드 20건은 상품군 분류부터 안 된다 |
| 심의 판정 정답률 | **정답이 없다.** 준법팀 확인 전이라 무엇이 진짜 지적인지 모른다 |
| 정밀도(precision) 측정 | **골드에 negative 목록이 없다.** "잡지 말았어야 할 것을 잡았나"를 잴 재료가 없다 |
| v1 vs v2 성능 비교 | v2 가 프롬프트를 전면 재작성해 **VLM 캐시가 미스**된다. 같은 조건 비교가 성립하지 않는다 → v2 를 **새 baseline 으로 선언**한다 |
| 신규 6건의 필드 회수 채점 | 골드가 없다. **coverage 지표 관측만** 한다 |
| `docs/review.html`·`tools/make_review.py` | HANDOFF-2026-08-18 §6 이 별도 트랙으로 지정 |

## 5. 지표를 읽는 규율

- 문장회수·필드회수는 **매 실행 다르다**. 단일 실행으로 개선/퇴행을 주장하지 않는다
- 결정론 층(`source ∈ {ocr, digital}`)만 단일 수치로 제시한다
- VLM 층은 **범위**로 제시하거나 반복 관측으로만 개선을 주장한다
- 숫자는 손으로 세지 않는다 — `tools/verify_numbers.py` 가 `out/` 에서 다시 뽑는다

## 6. 실행 절차

```bash
# ── 사전조건: WireGuard VPN (현재 미연결 — HTTP 000) ──
curl -s "${GEMMA_URL%/chat/completions}/models"     # 모델명 확인 필수

# 1) 골드 4문서 (채점 대상) — 캐시 기록
VLM_CACHE=r uv run python tools/run_extract.py

# 2) 신규 6문서 (커버리지 관측) — 입력이 out_new
VLM_CACHE=r uv run python tools/run_extract.py \
    --view-dir out_new/llm_view --out-dir out_new/extracted --parse-dir out_new/json \
    --only "1. 예금성상품(적립식)"        # 6건 각각

# 3) 채점
uv run python tools/verify_extract.py                          # 예금성 N/44 · 대출성 N/7
uv run python tools/verify_extract.py --ext-dir out_new/extracted

# 4) 결정론 확인 — 같은 캐시로 재실행 후 해시 대조
VLM_CACHE=p uv run python tools/run_extract.py
```

## 7. 규칙리스트 최종본 반영 (2026-08-19 연구소 전달)

`nh-data/pilot-data-set/NH_광고심의_규칙리스트_최종.xlsx` (849KB). 연구소 안내:
*"'제외 규칙' 값이 '-'인 규칙들만 대상으로 삼으면 될 것 같습니다."*

### 무엇이 달라졌나 (구 `…조문지도, 체크리스트 통합.xlsx` 대비, 전부 코드 집계)

| | 구 | 신 |
|---|---|---|
| 규칙 | 1,744건 | **2,024건** (+280) |
| 조문 | 263건 | **299건** (+36) |
| 체크리스트 칼럼 | 7 | **10** — `매뉴얼 원문 문구 (PDF 그대로)` 신설 |
| 칼럼 [14] | `MCP_구분` | **`제외 규칙`** 으로 교체 |

### `제외 규칙` 이 무엇을 걸러내나

| 제외 사유 | 건수(중복 포함) |
|---|---|
| 절차 관련 | 258 |
| 보고/제출/평가 의무 | 131 |
| 외부 데이터 연계 | 90 |
| 영상/음성 광고 | 78 |
| 시계열 및 이력 관리 | 9 |

**대상('-') 1,569건 / 제외 455건.**

전부 **정적 광고물 한 장만 보고는 판정할 수 없는 규칙**이다 — 이는 우리 스키마의
`obligation`(절차·수집·관측을 판정에서 제외) 및 `applicability` 설계와 **같은 취지**다.
즉 이 파일은 우리 설계를 뒤집는 게 아니라 **뒷받침한다.**

### 대상('-') 중 예금·대출 규칙

| | 구(필터 없음) | 신(대상만) |
|---|---|---|
| 예금·대출 포함 | 360건 | **306건** |
| └ 표시의무 | 198 | 183 |
| └ 금지 | 111 | 103 |
| └ 양식 | 30 | **17** |
| └ 절차 | 21 | **1** |

절차가 21→1로 줄어든 것이 필터의 효과다.

### 이번에 스키마를 바꾸지 않는 이유

우리 스키마는 **NH 체크리스트 축**(`DEP-*`/`LOAN-*` 97항목)에 붙어 있고, 규칙리스트는
별개 축(`R-*`)이다. 둘을 잇는 다리는 신 파일에 생긴 `매뉴얼 원문 문구 (PDF 그대로)`
칼럼이다(NH 심의사례의 `점검내용` 과 같은 원문). **연결 작업은 근거대장 갱신 때 하고,
런타임 스키마는 건드리지 않는다** — 이번 프로토타입의 채점 대상이 아니다.

**적용할 규약**: 근거대장에 규칙ID를 연결할 때 **`제외 규칙 == '-'` 인 것만** 쓴다.
