# 통합 설계 초안 — 우리 파싱을 nh-ad-compliance 에 붙이기

> **이 문서가 답하는 것**: 우리가 만든 것을 팀장님 레포에 **어떻게** 붙이나. 필드 하나씩
> 짝지어 보고, 안 맞는 자리를 먼저 찾아 둔다.
>
> **아직 코드는 없다.** 설계와 측정만이고, PR 도 안 올렸다.
> 작성 2026-08-07. 근거는 전부 **실제 코드·실제 산출물**이며 위치를 적었다.
> 대상 저장소는 **읽기만** 했다(`dev`, 커밋 `3cfcbb5`).

---

## 0. 세 줄 요약

1. **코드를 옮기는 게 아니라 어댑터 1개를 새로 쓰는 일이다.** 붙일 자리(`ParserAdapter`)는
   멤버가 `name`·`parse` 둘뿐이고, `"vlm-ocr"` 슬롯이 예약만 된 채 비어 있다.
2. **이미지·PDF 는 좌표를 손 안 대고 그대로 넘어간다**(라인 488건 전수 검증 통과).
   **막히는 건 HWP 하나**다 — 좌표가 아예 없어 계약을 통과할 수 없다.
3. **우리가 가져다줄 실제 가치는 `layoutBlocks` 다.** 대상의 `paddleocr` 는 이 배열을
   빈 채로 내보낸다. 우리는 영역 225개에 역할까지 붙인다.

## 1. 지금 양쪽이 어떻게 생겼나

```
[우리]  AdDocument ─ AdPage ─ Region ─ Line
        (독립 실행형: 러너가 파일을 읽어 out/json 에 쓴다)

[대상]  ParserRouter → ParserAdapter.parse(DocumentInput) → NormalizedDocument
        (HTTP 서비스: 컨테이너가 요청을 받아 계약 JSON 을 돌려준다)
                        ↑
                  여기에 우리가 들어간다
```

**형태가 다르다는 게 핵심이다.** 우리는 "파일 → 파일"이고 대상은 "요청 → 계약 객체"다.
그래서 우리 파이프라인은 그대로 두고, **껍데기(어댑터)를 새로 씌우는** 모양이 된다.

## 2. 필드 대응표 — 하나씩 짝지어 보기

### 2-1. 문서 단위: `AdDocument` → `NormalizedDocument`

| 우리 | 대상 | 어떻게 | 비고 |
|---|---|---|---|
| `doc_id` | `documentId` | `f"doc-{sourceFileId}"` | 대상 형식을 따른다 |
| `source_file` | `sourceFileType` | 확장자만 소문자로 | |
| — | `sourceFileId` · `reviewId` | **요청에서 온다** | 우리가 만들지 않는다 |
| `pages[]` | `pages[]` | 페이지 번호·크기 | HWP 는 크기 생략 가능(`None` 허용) |
| `Region[]` | `layoutBlocks[]` | **§2-3** | ⭐ 우리 강점 |
| `Line[]` | `textBlocks[]` | **§2-2** | |
| — | `tables[]` | **빈 배열** | 우리 IR 에 표 모델이 없다(표도 라인으로 평탄화됨) |
| `notes[]` | `warnings[]` | 선별 변환 | **§3-4** |
| — | `confidence` | `min(모든 블록)` 을 대상이 계산 | **§3-2 위험** |
| — | `parserName` 등 4종 | 어댑터가 고정값으로 | 문서와 모든 블록이 **같아야 한다**(검증기 있음) |
| — | `rawArtifactRef` | 필수·빈 문자열 불가 | 우리 `out/json` 경로를 넣으면 자연스럽다 |
| `product_group` · `ad_type` | **자리 없음** | — | **§4 STAGE_3 논의와 함께** |
| `category_source` | **자리 없음** | — | 분류 근거. `warnings` 로 실을지 논의 |

### 2-2. 글자 단위: `Line` → `TextBlock`

| 우리 | 대상 | 어떻게 |
|---|---|---|
| `text` | `rawText` · `normalizedText` | 그대로(정규화 규칙은 추후) |
| `bbox [x0,y0,x1,y1]` | `coordinate` | `x=x0, y=y0, w=x1-x0, h=y1-y0` + 정규화값 4개 |
| `confidence` | `confidenceScore` | `None` 이면 채울 값을 정해야 한다 → **§3-3** |
| — | `confidenceStatus` | 점수에서 유도(**임의로 못 적는다**, 검증기 있음) |
| `source`(ocr/digital/vlm_sweep) | **자리 없음** | 우리만의 개념. `coordinateConfidence` 로 간접 표현 → **§3-1** |
| `vlm_reading`(라인 후보) | **자리 없음** | 후보 판독을 담을 칸이 계약에 없다 → **§3-4** |

### 2-3. 영역 단위: `Region` → `LayoutBlock` ⭐

**여기가 우리가 가져다줄 것이다.**

| 우리 | 대상 | 어떻게 |
|---|---|---|
| `region_id` | `layoutBlockId` | 그대로 쓸 수 있다(이미 `p1_r004` 꼴로 고유) |
| `role`(제목·본문·유의사항 등 9종) | `layoutType` | **문자열 자유** — 우리 값을 그대로 넣을 수 있다 |
| `bbox` | `coordinate` | 라인과 동일 |
| `lines[]` | `relatedTextBlockIds[]` | 그 영역에 속한 TextBlock id 목록 |
| `role_confidence` | `confidenceScore` | 필수 필드 |
| `layout_score` · `role_rule` · `card_no` · `vlm_reading*` | **자리 없음** | 진단용 부가정보. 계약 밖 |

> `layoutType` 이 자유 문자열이라 **우리 역할 이름(한글 9종)을 손실 없이 넘길 수 있다.**
> 다만 대상 심의 엔진이 이 값을 아직 안 읽으므로(§4), 당장은 화면·감사용이다.

## 3. 막히는 자리 4곳 — 실측으로 재고 해법을 정했다

### 3-1. ⚠️ HWP 는 좌표가 없어 계약을 못 통과한다 (**최우선**)

**측정**

```
004 (HWP) : canvas 0×0 · 라인 12개 · bbox 있는 라인 0개 · confidence 전부 None
나머지 4문서 : bbox 없는 라인 0건
```

**왜 막히나** — `Coordinate` 는 `sourceWidth: gt=0` 을 요구한다. 캔버스가 `0×0` 이라 좌표
객체 자체를 만들 수 없다. 그런데 `TextBlock` 검증기가 이렇게 막는다:

```python
if self.coordinate is None and not self.text_path:
    raise ValueError("a text block requires a coordinate or textPath")
```

**선택지**

| 안 | 내용 | 평가 |
|---|---|---|
| **가** | 1차 PR 범위를 **이미지·PDF 로 한정**하고 HWP 는 다음 PR | ⭐ **권고.** 488/500 라인이 이미 통과하니 범위를 줄여도 가치가 그대로다 |
| 나 | `textPath` 를 만들어 넘긴다(문단 인덱스 등) | 형식을 대상과 합의해야 하고, 대상 HWP 경로(`rhwp_app`·`document_processor_app`)와 **중복될 수 있다** |
| 다 | 가짜 캔버스 크기를 지어낸다 | ✗ **하면 안 된다.** 없는 좌표를 있다고 말하는 것이라 화면 하이라이트가 엉뚱한 곳을 가리킨다 |

> 대상 저장소에는 이미 HWP 를 다루는 서비스가 둘 있다(`rhwp_app.py`·`document_processor_app.py`).
> **우리 HWP 트랙이 필요한지부터** 팀장님과 확인하는 게 순서다 — 중복 구현일 수 있다.

### 3-2. ⚠️ 빈 텍스트 11건이 문서 전체를 "판독 불가"로 떨어뜨린다

**측정** — `confidence == 0.0` 인 라인 11건, **전부 텍스트가 빈 문자열(`''`)**.
OCR 이 상자는 잡았는데 글자를 못 읽은 것들이다.

**왜 위험한가** — 대상은 문서 신뢰도를 이렇게 계산한다:

```python
confidence = min((float(block["confidenceScore"]) for block in blocks), default=0.0)
```

`0.0` 이 하나라도 섞이면 문서 전체가 `0.0` → `<0.50` → **`UNREADABLE`**. 나머지 488줄을
아무리 잘 읽었어도 문서가 통째로 "못 읽음"으로 강하된다.

**해법 — 우리 쪽에서 거른다 (확정)**

빈 문자열은 애초에 **글자 블록이 아니다.** `rawText` 가 비어 있는 걸 내보낼 이유가 없다.
"대상 계산식을 바꾸자"고 할 사안이 아니라 우리가 안 보내면 끝난다.
다만 **버리지 말고 `warnings` 에 "검출됐으나 판독 실패 N건"으로 남긴다** — 조용히 사라지면
"OCR 이 놓친 자리"라는 정보까지 없어진다.

### 3-3. HWP 라인은 `confidence` 가 `None` 인데 계약은 필수다

`confidenceScore` 는 필수(`ge=0, le=1`)다. `None` 을 그대로 두면 못 만들고, `0.0` 을 넣으면
§3-2 와 같은 이유로 문서가 죽는다.

**해법** — HWP 텍스트는 **OCR 이 아니라 파서가 그대로 읽은 정본**이므로 추정이 아니다.
`1.0`(또는 `0.95`)이 사실에 맞다. 단 이건 §3-1 의 "가" 안을 택하면 **1차 PR 에선 안 나온다.**

### 3-4. 통짜 스윕 라인은 좌표가 "가로 전체"다

**측정** — `vlm_sweep` 라인 15건, **15건 모두** `bbox = [0, y0, canvas_w, y1]`.

계약 **검증은 통과한다**(폭>0, 경계 내). 문제는 검증이 아니라 **뜻**이다 — 실제 글자는
그 가로줄 어딘가에 있는데 좌표는 줄 전체를 가리킨다. 그대로 넣으면 검수 화면 하이라이트가
엉뚱하게 넓은 띠를 칠한다.

**해법 — `coordinateConfidence` 를 낮게 준다**

대상에 이미 받아 줄 장치가 있다. 낮은 좌표 신뢰도는 표시 방식을 `LIST_ONLY` 로 떨어뜨린다
(`results.py:345`, 테스트 `(0.49, "LIST_ONLY", "NOT_LOCATED")`). 즉 **"글자는 맞는데 위치는
못 믿는다"를 계약이 이미 표현할 수 있다.** 스윕 라인은 `coordinateConfidence < 0.5` 로 준다.

> 대상 헬퍼 `text_block()` 은 `coordinateConfidence = confidenceScore` 로 **같이 묶어 둔다**
> (`service.py:134`). 우리는 둘을 갈라야 하므로 이 헬퍼를 그대로 못 쓰고 직접 만들어야 한다.

## 4. STAGE_3(스키마 필드 추출)의 자리 — **고르지 않는다**

대상의 심의 엔진(`ReviewResultEngine`)에는 **필드 추출 결과를 받을 인터페이스가 없다.**
따라서 이건 우리가 정할 일이 아니라 팀장님과 합의할 사안이다. 세 갈래만 정리한다.

| 안 | 범위 | 위험 | 필요 |
|---|---|---|---|
| **가. 파싱만 먼저** | 어댑터 1개. STAGE_3 는 우리 저장소에 남긴다 | 낮음 — 계약을 안 건드린다 | ADR 1건(신규 어댑터) |
| **나. STAGE_3 를 후단 서비스로** | 어댑터 + 별도 서비스 + 결과 저장 자리 | 중간 — 새 계약을 만들어야 한다 | ADR 2건+, DB 스키마 |
| **다. 심의 엔진 교체** | 대상 판정 로직을 우리 스키마 기반으로 | 높음 — 기존 판정·화면·테스트가 흔들린다 | ADR 다수, 합의 필수 |

**참고(권고 아님)**: 「가」로 시작하면 §3 의 문제 중 3-1 만 남고 나머지는 어댑터 안에서 끝난다.

## 5. 그래서 순서는

```
지금  ── 설계 확정 (이 문서) ─────────────────── ✅ 여기까지 완료
 │
 ├─ 1단계  IR 변환기 + 계약 테스트
 │         우리 out/json 을 NormalizedDocument 로 바꾸는 함수 하나.
 │         대상 저장소 없이 우리 쪽에서 단독 검증 가능
 │         (계약 패키지만 설치해 pydantic 검증을 돌린다)
 │         → 합격 기준: 488 라인 · 224 영역이 검증 통과, 실패 0
 │
 └─ 2단계  서비스 껍데기 + compose + ADR + 문서   ← 실제 PR
```

**1단계를 먼저 떼는 이유**: 변환기는 **대상 저장소를 안 건드리고도** 맞는지 틀린지 판정할 수
있다. 여기서 계약 위반을 다 잡아 두면, PR 에는 "붙이는 일"만 남는다.
