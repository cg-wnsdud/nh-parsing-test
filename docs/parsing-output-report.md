**㉠ 좌우 3분할 — 카드를 먼저 나눠야 한다**

표지 / EVENT1 / EVENT2 가 좌우로 나란하다. 좌표만 보고 위→아래로 읽으면 **EVENT1 과 EVENT2
문장이 한 줄씩 번갈아** 나온다. 그래서 카드를 먼저 구분하고 **카드 안에서** 읽는 순서를 정한다.

픽셀 밀도가 센 덩어리 (모델 호출 0회):

```
p1  1번 x_ratio 0.04~0.33 글자량 33%   2번 0.36~0.64 34%   3번 0.68~0.96 28%
p2  1번 x_ratio 0.04~0.33 글자량 58%   2번 0.36~0.63 38%
p3  덩어리 1개 → 단일패널 → VLM 호출 안 함
```

**판단 로그**: `카드 개수 불일치(VLM 판단 채택): 밀도 3장 vs VLM 2장`.
그 결과 표지 헤드라인이 EVENT1 카드에 묶여 ① 결과에서 EVENT1 내용 중간에 끼어 나온다.
**각 카드의 내용은 안 섞였고** 표지 헤드라인 1개의 소속만 흔들린다. 안 고치는 이유:
**좌우 분할 샘플이 1건뿐**이라 1건에 맞춰 규칙을 바꾸면 과적합이다.

**㉡ p3 — OCR 을 아예 안 돌렸다**

글자 503자, 한글 317자, 이미지 면적비 0%. 믿을 만한 글자 레이어가 있어 **PaddleX 를 한 번도
안 불렀다.** 영역 2개에 라인 25개 — 텍스트가 통째로 들어왔다.

`p3_r001` 정본에 공백이 전부 없는 게 보인다(`[NHBenefit]모여봐요,올원모임으로!시즌3`) —
디지털 추출이 공백 문자를 버리고 이어붙이기 때문이다.

**㉢ VLM 이 틀린 사례 — "정본을 왜 안 덮는가"의 증거**

```
p1_r019   정본 : Pay / 30,000원 / 네이버페이포인트3만원 / (추첨15) / 내지2
          후보 : 네이버페이 포인트 3만원 / (추첨 10명)          ← 원본은 15명!
          관계 : diverged  정밀도 0.8  커버리지 0.167
```

**원본은 `추첨 15명`이다.** 미리보기 이미지로 확인했고, 같은 문서 p3 의 디지털 텍스트 레이어가
`네이버페이포인트3만원권(추첨15명)` 으로 **독립적으로 증언**한다. 표기가 훨씬 깔끔한 VLM 후보가
**인원수를 10명으로 바꿔 썼다.** 경품 당첨 인원이라 광고 심의에서 중요한 숫자다.

**만약 VLM 판독으로 정본을 덮었다면 광고에 없는 숫자가 심의 대상 값이 된다.** 지금은 둘 다
남아 있고 코드가 `불일치` 딱지를 붙여 먼저 확인할 것으로 올려놨다.

**㉣ 잘림 경보 4건 중 1건은 오탐**

```
p1_r011  정본 '지원금10만원 / (선착순1,000팀) / 내지1'   후보 '지원금 10만원 (선착순 1,000팀)'
         → tail_cut "17% 소실"  ← 오탐
```

낱줄 귀속이 페이지 꼬리표 `내지1` 을 본문 영역에 붙였고, VLM 이 그걸 안 읽은 게 "잘림"으로
잡혔다. 같은 이유로 `p1_r019` 에는 `내지2` 가 붙어 있다.

**㉤ 심의필 문구 — 정본과 후보가 같은 오독을 한 사례**

```
원본(크롭 확인)  : 준법감시인심의필 2025-0000 (2025.00.00. - 2025.00.00.)
정본 p1_r002    : 준법감시인심의일 2025-0000 (2025.00.00-2025.00.00)    ← 필 → 일
후보            : 준법감시인심의일 2025-0000 (…)                        ← 같은 오독
관계 딱지        : same                                                ← 경보 없음

```

**2층 대조는 의견이 갈릴 때만 작동한다.** `eval_report.md` 가 이걸 "파싱 결과에 없음"으로 찍는데
정확히는 **파싱은 그 영역을 잡았고 한 글자를 잘못 읽었다.**
