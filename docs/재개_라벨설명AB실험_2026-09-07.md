## 지금까지 된 것

| | r1 | r2 | r3 | r4 | r5 |
|---|---|---|---|---|---|
| A | 완료 | 완료 | 완료 | 완료 | 남음 |
| B | 완료 | 완료 | 완료 | 남음 | 남음 |
| C | 완료 | 완료 | 완료 | 남음 | 남음 |

**3반복 완전 세트는 확보됨.** 남은 5회는 표본을 늘리는 것이지 없으면 분석이 막히는 것은
아니다. 시간이 없으면 r1~r3 만으로 먼저 읽어도 된다.

중단 시점에 부분 완료였던 `B_r4` 는 지웠다(부분 산출물로 채점하면 분모가 틀어진다).

## 실험이 무엇인가

`[항목 정의]` 블록에 무엇까지 넣을지만 바꾼다. 광고 이미지·영역 텍스트·응답 스키마·질문은
세 조건 모두 동일하다.

| 조건 | 주는 것 | 분량(적립식) |
| --- | --- | --- |
| A | 항목명 + 예시 1줄 (종전 운영) | 603자 |
| B | A + 구분 설명 | 1263자 |
| C | B + 포함범위·구별기준 | 2986자 |

예시는 세 조건 모두 **기존 팩의 같은 1줄**로 고정했다 — 예시가 늘면 설명 덕인지 예시
덕인지 못 가린다. 코덱스 `instructions` 10개는 이번에 **안 넣었다**(변수를 늘리지 않으려고).

구현: [ad_template.py](../src/nh_parsing/ad_template.py) 의 `_LABEL_DEFS_MODE` /
`_label_semantics` / `_gubun_definitions`. 환경변수 `NH_LABEL_DEFS` 를 안 주면 **A =
기존 동작 그대로**라 다른 작업에 영향이 없다. 설명 원본은
`out_labeling_schema_20260907/labeling_catalog.json`(코덱스 산출물).

## 실험 조건 (재개해도 지켜야 함)

- **파싱은 `out_0907_label_defs_v2/base/parse` 하나를 세 조건이 공유한다.** 조건마다
  재파싱하면 OCR 흔들림이 섞여 무엇 때문에 달라졌는지 못 가린다. 스크립트가 이 폴더를
  각 조건 폴더로 복사한다.
- **VLM 캐시 off** (`VLM_CACHE=""`). 켜면 B·C 가 A 의 답을 재생한다.
- **VLM 판독 off** (`REGION_READING_MODE` 기본 `off`). 채점 대상은 OCR 정본이다.
  5개 문서 229개 영역 전부 `selected_text_source = parser_primary_text` 로 확인함.
- **`--read-tables` 안 줌.**

## 채점 기준

라벨 골드가 있는 문서는 **올원e적금 1건뿐**이다. `gold/` 의 001·002 는 영역 경계
골드(박스 좌표만)라 라벨 정답이 없다. 나머지 4건에서는 "무엇이 달라졌나"만 나온다.

채점기는 `actual == expected` 인 **집합 완전일치**다
([evaluate_region_gold.py:129-133](../tools/evaluate_region_gold.py#L129-L133)).
골드가 라벨 없다고 한 블록에 라벨을 붙이면 fail — **과다 배정이 감점된다.**

## 판정 규칙

```
같은 조건 반복 간 불일치(잡음) = N%
A↔C 차이                     = M%

M > N  → 설명이 실제로 영향을 준다
M ≤ N  → "이 표본으로는 판정 불가"  (차이 없음이 아니다)
```

같은 코드 재실행만으로 골드 33블록 중 4개(12%p)가 움직인 전례가 있다. 표본이 1건뿐이라
통계적 힘이 약한 것이 근본 제약이고, 실행 횟수로는 못 메운다.

## 재개 전에 세워 둔 예측 (A 조건 1회 실측 기준)

A 조건에서 틀린 9건의 내역:

| 부류 | 건수 | 사례 |
| --- | --- | --- |
| 회사명 남발 | 5 | `중도해지이율 및 만기 후 이율 : NH농협은행 영업점…` → 기대 [만기후이율,중도해지이율] / 실제 +회사명 |
| 표제·조각 오인 | 3 | `"유의사항"` 표제 자체에 유의사항 라벨, `"NH"` 조각에 상품명 |
| 진짜 의미 혼동 | 1 | `마케팅 동의 우대이자율은 반드시…` → 기대 유의사항 / 실제 우대금리 |

코덱스 카탈로그의 `회사명` 항목에 이런 구별기준이 있고 **C 조건에만** 들어간다:

> 구별) 우대조건 속 은행명 언급만으로 그 조건 전체를 회사명으로 분류하지 않는다.

따라서 예측:

- **A → B** 에서 부류 3(의미 혼동)이 줄어야 한다 — 설명이 뜻을 알려주므로
- **B → C** 에서 부류 1(회사명 남발 5건)이 줄어야 한다 — 구별기준이 바로 그것을 금지하므로
- C 에서도 회사명 5건이 그대로면, 구별기준을 문장으로 주는 것만으로는 부족하다는 뜻

## 영역 경계로 실패한 3건 (라벨과 무관, 파싱 쪽 숙제)

세 건 다 글자는 있고 **두 영역으로 갈렸다**.

- `b014` `최고 연3.6%p`(r013) / `우대조건 충족하는 경우 만기해지 시 적용`(r014)
  → 숫자와 그 조건이 끊겼다. 심의 관점에서 실제 손해.
- `b015` 우대조건 ①②(r014) / ③(r015) → 세 항목 목록이 쪼개졌다.
- `b025` `<만기 시 예상 수취이자 예시>`(r025) / 본문·`70,200원`(r026) → 표제와 본문이 갈렸다.

원문보존 4/14 도 별개 실패 10개가 아니라 위 b015·b025 에 딸린 규칙 10개가 함께 떨어진
것이다. OCR 이 `① → 1`, `「」 → []`, `⑦번동의서 → 번동의서`, `동의 시¹ → 동의 시1` 로
읽은 것도 같이 확인됐다. **각주 번호 `¹` 이 보통 `1` 이 되는 것은 값과 각주 참조를
구별할 수 없게 만든다** — 별건으로 잡을 것.

## 아직 안 정한 것

1. 골드 없는 4건에서 A↔C 가 갈린 영역을, 내가 원본 이미지와 대조해 판정할지 / 목록만
   남기고 담당자에게 넘길지. (20개 안쪽이면 전수 대조 가능)
2. VLM 판독(`REGION_READING_MODE=shadow REGION_READING_SCOPE=all`) 켜고 끄는 비교를
   별도로 돌릴지. shadow 는 정본을 안 바꾸고 `vlm_region_reading` 칸에만 적으므로 안전하다.
   원문보존 4/14 를 올릴 여지가 거기 있다.
3. 코덱스가 담당자 판단으로 넘긴 4건 — 복수 라벨 허용 범위, 표제 없는 영역의 기준,
   회사명 중복 배정, 다상품 템플릿 선택.
4. 같은 줄에 두 라벨을 동시에 허용할지. 지금은 프롬프트가 "범위는 겹치지 않아야
   한다"고 막고 있어 `completeness` 검증과 함께 풀어야 한다.
