## 표기

| 기호 | 주체 | 무엇 |
|---|---|---|
| 🅿 | **PaddleX** | PP-StructureV3 — 텍스트 검출·인식·레이아웃 블록 |
| 🅶 | **Gemma VLM** | 의미 판단 (역할·카드·교정·분류) |
| ⬛ | **순수 코드** | 좌표 계산·규칙·픽셀 통계. 모델 호출 없음 |

**원칙**: 의미 판단은 모델이, 검산은 코드가 한다. 코드가 규칙으로 우열을 정하지 않는다.

## 전체 흐름

```
입력 (PDF / PNG / HWP)
  │
  ├─ 0. 라우팅 ─────────────────────────────────── ⬛
  │     PDF → 페이지별 트리아지(structured / hybrid / scan_like)
  │     HWP → 텍스트·표는 디지털 정본, 내장 이미지는 OCR 트랙
  │
  ├─ 1. 글자 획득 ──────────────────────────── ⬛ + 🅿
  │     ① 밀도 기반 타일 분할          ⬛
  │     ② 레이아웃 + OCR (타일당 1회)   🅿
  │     ③ 좌표 복원 · 중복 제거         ⬛
  │     ④ 디지털 우선 병합              ⬛
  │     ⑤ 영역 조립                     ⬛  → 여기서 남은 게 '미배정 낱줄'
  │
  ├─ 2. 의미 판정 ───────────────────────────── ⬛ + 🅶
  │     ⑥ 카드 게이트                   ⬛   스크롤·단일패널이면 호출 안 함
  │     ⑦ 카드 배정                     🅶   1회 (밀도 개수를 증거로 첨부)
  │     ⑧ 역할·섹션 판정                🅶   페이지당 1회
  │     ⑨ 장식예시 격리                 ⬛   ⑧의 판정을 소비해 태깅
  │     ⑩ 좌표 귀속                     ⬛
  │     ⑪ 내용 귀속                     🅶   ⑩에서 남은 낱줄만 + 좌표 게이트 검증
  │
  ├─ 3. 통합 판독 ────────────────────────────── 🅶
  │     ⑫ 밴드 통합판독                 🅶   밴드당 1회 (교정 + 누락 회수 동시)
  │     ⑬ 통짜 스윕                     🅶   페이지당 1회 (대형 장식 타이포)
  │     ⑭ 스윕-OCR 중복 정정            🅶   중복 1건당 1회 (상한 8)
  │     ⑮ 저신뢰 재판독                 🅶   conf<0.80 라인 (상한 12)
  │     ⑯ 읽기순서 정렬 · 진단           ⬛
  │     ⑰ 광고 분류                     🅶   문서당 1회
  │
  └─ 4. STAGE_3 스키마 추출 (별도 프로세스) ─── 🅶 + ⬛
        5그룹 분할 호출                  🅶   문서당 5회
        부재 4분류 · 유령 이벤트 제거     ⬛
        bbox 재부착                      ⬛

산출물: out/json (IR) · out/llm_view (STAGE_3 입력) · out/extracted (필드)
```

## 단계별 상세

### 0. 라우팅 ⬛

| 입력 | 처리 |
|---|---|
| PDF `structured` | **OCR 안 돌림.** 디지털 텍스트가 정본 (003 p3) |
| PDF `hybrid` | 디지털 + OCR 병행, 겹치면 디지털 우선 |
| PDF `scan_like` | 전부 OCR. 내장 래스터 **원본 해상도**로 렌더(업스케일 금지) |
| PNG | 전부 OCR |
| HWP | 텍스트·표는 사내 파서(디지털 정본), 내장 이미지만 OCR 트랙 |

판정 기준: 텍스트 20자 미만이거나 U+FFFD 비율이 높으면 텍스트 레이어 불신.

### 1. 글자 획득 — 여기가 OCR

**① 밀도 기반 타일 분할** ⬛ — [bands.py](../../src/nh_parsing/bands.py)

세로로 긴 광고(6000px 이상)는 한 번에 못 보내므로 잘라야 한다. 예전엔 1600px마다
기계적으로 잘랐는데 **글자를 반토막 냈다.** 지금은 국소 대비(에지)로 글자 있는 행을
찾아 **글자량이 고르게 나뉘는 자리**를 고르고, 그 자리를 **글자 없는 행으로 스냅**한다.

- 밝기가 아니라 대비를 쓰는 이유: 색 배경 패널을 글자로 오인하지 않기 위해
- 높이 상한(1600px)이 필요한 이유: 상한을 빼면 성긴 구간이 2157px짜리 조각이 되고
  레이아웃 블록이 84→62로 줄어 작은 영역이 큰 영역에 흡수된다(002 실측)

**② 레이아웃 + OCR** 🅿 — 타일당 1회. 검출·인식·레이아웃 블록을 한 번에 받는다.

**⑤ 영역 조립** ⬛ — 레이아웃 블록에 라인을 좌표로 분배. 블록이 없으면 수직 간격
군집으로 폴백. **어느 블록에도 안 들어간 라인이 `unassigned_lines`** 가 되고, 이게
뒤의 귀속 단계(⑩⑪)가 존재하는 이유다.

### 2. 의미 판정 — 여기가 VLM

**⑥ 카드 게이트** ⬛ — 세로 스크롤(높이/폭 ≥ 2)이거나 단일 패널이면 **호출조차 안 한다.**
결정론 라우팅으로 헛호출을 막는다.

**⑦ 카드 배정** 🅶 — 개수는 픽셀 밀도가 결정론적으로 세고, **배정은 VLM**이 한다
(전폭 헤드라인처럼 어느 컬럼에도 안 속하는 요소는 좌표로 못 정하기 때문).
밀도 관측을 **증거로 프롬프트에 실어** 1회만 묻는다 — 예전엔 밀도와 어긋나면 같은
질문을 3번 더 던졌는데, 새 정보가 없으니 같은 답만 돌아왔다.

**⑧ 역할·섹션 판정** 🅶 — 영역을 의미 섹션(헤드라인/유의사항/장식예시 등)으로 묶고
`group_no`를 부여. **OCR 정본만 보고 판정한다**(VLM 후보는 안 씀 — 비결정성 격리).
호출 6회로 전체 시간의 20%를 쓰는 가장 무거운 단계다(호출당 33초).

**⑨ 장식예시 격리** ⬛ — 앱 목업 화면 등을 태깅한다. **삭제가 아니라 표시**다.
예전엔 아예 제외했는데, 003의 헤드라인이 장식으로 판정돼 통째로 빠졌고 STAGE_3가
본 적도 없는 내용을 "필드 미발견"으로 집계했다(5문서 33영역 소실).

**⑩⑪ 미배정 귀속** — 1단은 좌표(⬛), 2단은 내용(🅶). 2단 결과는 좌표 정합 게이트로
교차검증해 어긋나면 반려한다.

### 3. 통합 판독

**⑫ 밴드 통합판독** 🅶 — [pipeline.py::_merged_band_read](../../src/nh_parsing/pipeline.py)

**OCR이 본 것과 같은 크롭**을 VLM에도 주고 "이 영역들을 고쳐라 + 목록에 없는 문구를
찾아라"를 한 번에 묻는다. 원래 두 단계였던 것을 합친 결과 호출이 122→65회로 줄었다.

- 영역은 **겹침이 가장 큰 밴드 하나**에만 배정한다. 밴드가 200px 겹치므로 "중심이
  범위에 들면"으로 고르면 24%가 두 밴드에 중복 배정된다(2026-07-29 수정)
- 영역이 경계에 걸치면 **크롭을 넓힌다**(컷을 옮기지 않는다 — 옮기면 밀도 분할이 깨짐)

붙는 결과는 **후보**(`vlm_reading`)일 뿐 정본을 안 덮는다. 관계를 경계 기준으로 판정해
(`tail_cut` / `head_drop` / `expanded` / `diverged` / `same`) 딱지를 붙인다 —
토큰 겹침 점수만으로는 **뒤가 잘린 판독이 정밀도 만점**을 받기 때문이다.

**⑭ 스윕-OCR 중복 정정** 🅶 — 스윕이 회수한 문구가 기존 라인의 다른 판독이면
(`10.1%p` vs `① 0.1%p`) 그 자리를 고해상 재판독해 **VLM이 심판**한다. 규칙으로
우열을 정하지 않는다.

**⑯ 진단** ⬛ — 레이아웃이 통째로 놓친 블록이 있으면 노트로 남긴다
([layout_gap.py](../../src/nh_parsing/layout_gap.py)). 미배정 낱줄이 27개라는 숫자만으로는
"레이아웃이 깨진 것"인지 "원래 흩어진 화면"인지 모르므로, **응집한 덩어리만** 골라낸다.

### 4. STAGE_3 스키마 추출

스키마를 5그룹(상품기본 / 금리 / 의무고지 / 위험표현 / 이벤트)으로 나눠 호출한다.
한 번에 57필드를 다 물으면 응답이 길어져 배열 선두가 비는 퇴행이 난다.

부재 4분류(미표시 / 해당없음 / 확인필요 / 판정제외)는 **스키마 메타데이터를 코드로
평가**한다 — 모델 호출을 늘리지 않는다.

## 검증 도구

| 도구 | 대상 | 지표 | 현재 |
|---|---|---|---|
| `evaluate.py` | `out/json` | 분류 / 섹션 / 문장 | 9/9 · 37/44 · 236/242 |
| `verify_extract.py` | `out/extracted` | 필드 회수 | 44/44 |
| `make_review.py` | 전부 | 육안 검수 HTML | `out/review.html` |
| `vlm_cache.py` | — | A/B 결정론 (`=r` 기록 / `=p` 재생) | 개발 전용 |

`make_review.py`가 그리는 것: 원본 위 bbox 하이라이트, STAGE_3 필드와 근거 연결,
**OCR 정본 ↔ VLM 후보 대조**(갈린 영역만, 위험한 관계를 위로).

> ⚠️ `VLM_CACHE=p`(재생)는 **프롬프트를 바꾸는 변경의 A/B에 쓰면 안 된다.** 키가
> 달라져 전량 캐시 미스가 나는데, 재생 모드는 실호출로 넘어가지 않고 그 단계를
> 실패시킨다. 실패가 폴백에 먹혀 **품질 대폭락처럼 보인다.**
