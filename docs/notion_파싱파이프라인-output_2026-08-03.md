# 파싱 파이프라인 구조 및 결과

> **이 파일은 노션에 붙여넣기 위한 원고입니다.** 저장소 정본은
> [handoff.md](handoff.md)(스키마·산출물 계약)와
> [architecture/pipeline-map.md](architecture/pipeline-map.md)(내부 동작)이고,
> 여기는 그 둘에서 팀 공유에 필요한 부분만 뽑아 **2026-08-03 실행 결과 스냅샷**을
> 붙인 것입니다. 규정이나 코드가 바뀌면 정본을 먼저 고칩니다.
>
> 📷 표시는 **캡처 이미지를 붙일 자리**입니다. 그 줄을 지우고 이미지를 넣으면 됩니다.
> 붙일 파일 경로가 그 줄에 적혀 있고, 파이프라인이 **자동 생성한 파일**이라
> 따로 캡처하지 않고 그대로 올리면 됩니다.

---

## 0. 한 줄 요약

광고 파일(PDF·PNG·HWP)을 넣으면 **화면의 글자를 좌표와 함께 뽑고**, 심의 스키마에
맞춰 **구조화된 값**으로 만듭니다. 값이 없으면 **왜 없는지**까지 분류합니다.
**"이 광고가 규정 위반인가"는 판정하지 않습니다** — 그건 다음 단계(RAG/DB 엔진 +
심의 담당자)의 몫입니다.

| | |
|---|---|
| 기준일 | 2026-08-03 |
| 실행 조건 | 샘플 5문서 전량, **캐시 없이 처음부터** 재실행 |
| 입력 | 광고 파일 5건 (PDF 2 · PNG 2 · HWP 1) |
| 출력 | 문서당 3개 파일 (`out/json` · `out/llm_view` · `out/extracted`) |
| 처리 시간 | **전체 25분 7초** (파싱 14분 37초 + 스키마 추출 10분 28초 + 채점 2초) |

## 1. 전체 흐름

```
입력 (PDF / PNG / HWP)
  │
  ├─ 0단계  라우팅 ─────────────────────────  코드
  │     PDF는 페이지마다 "글자 레이어가 믿을 만한가" 판정
  │     HWP는 사내 파서로 텍스트·표를 그대로 추출(OCR 불필요)
  │
  ├─ 1단계  글자 획득 ────────────────── 코드 + OCR
  │     ① 글자 밀도로 이미지를 조각냄  ② PP-StructureV3 OCR
  │     ③ 좌표 복원·중복 제거  ④ 디지털 텍스트 우선 병합  ⑤ 영역 조립
  │
  ├─ 2단계  구조 정리 ────────────── 코드 + VLM
  │     ⑥ 카드형 광고인지 게이트  ⑦ 카드 배정  ⑧ 영역 역할 판정
  │     ⑨ 어디에도 안 붙은 낱줄을 좌표로 귀속 (순수 코드)
  │
  ├─ 3단계  통합 판독 ──────────────────────  VLM
  │     ⑩ 구간별 재판독(교정 + 누락 회수 동시)  ⑪ 전체 훑기
  │     ⑫ 중복 판독 정정  ⑬ 저신뢰 줄 재판독  ⑭ 읽기순서 정렬  ⑮ 광고 분류
  │
  └─ 4단계  스키마 추출(STAGE_3) ─────────  VLM + 코드
        5그룹으로 나눠 질의 → 필드 값 + 근거 → 부재 4분류 → 좌표 재부착

산출물:  out/json (전체 기록)  ·  out/llm_view (RAG용)  ·  out/extracted (DB용)
```

**설계 원칙 — 의미 판단은 모델이, 검산은 코드가 합니다.**
코드가 규칙으로 "이게 맞다"를 정하지 않고, 모델이 판단한 것을 코드가 좌표·문자열로
교차검증합니다.

### 단계별로 누가 무엇을 하나

| 단계 | 하는 일 | 주체 | 왜 필요한가 |
|---|---|---|---|
| 0. 라우팅 | 파일 종류·글자 레이어 판정 | 코드 | HWP·디지털 PDF는 OCR이 오히려 손해 |
| 1. 글자 획득 | 이미지에서 글자+좌표 추출 | PaddleX OCR | 광고물 대부분이 캡처 이미지 |
| 2. 구조 정리 | 좌우 카드 구분, 영역 역할 분류, 낱줄 귀속 | 코드 + VLM | 좌우 분할 광고는 좌표만으론 읽는 순서가 섞임 |
| 3. 통합 판독 | OCR이 놓치거나 틀린 글자 회수 | Gemma VLM | 작은 글씨·회전 텍스트·장식 폰트 |
| 4. 스키마 추출 | 스키마 필드에 값 채우기 + 근거 지목 | Gemma VLM | DB에 넣으려면 라인이 아니라 필드여야 함 |

### 파싱 단계에서 **하지 않는** 것

- **의미 섹션 묶음을 만들지 않습니다.** 예전에는 영역들을 "헤드라인 / 이벤트안내 /
  상품유의사항" 같은 의미 단위로 묶었는데 **없앴습니다.** 이유는 세 가지입니다.
  ① 같은 입력을 두 번 돌리면 결과가 달라졌습니다(4문서 중 3문서 불일치 실측).
  ② 다음 단계에 넘길 계약(NormalizedDocument v1: 문서→페이지→블록)에 담을 자리가
  없었습니다. ③ "이 영역들이 한 의미 단위인가"는 파싱이 답할 질문이 아닙니다.
  → 지금은 **영역을 읽는 순서대로 평면 나열**합니다. 순서 자체가 화면 흐름을 담습니다.
- **위반 여부를 판정하지 않습니다.** 과장 표현 후보는 수집하지만 "위반"이라고
  단정하지 않고, 값이 없는 필드도 "표시 의무가 있는데 없다"는 **사실**까지만 적습니다.

## 2. 미리보기 그림 읽는 법

파싱이 이미지에서 글자를 어디서 어떻게 잡았는지를 **원본 위에 박스로 그려** 자동
저장합니다(`out/previews/*.jpg`).

| 표시 | 뜻 |
|---|---|
| **가는 마젠타 선** | **라인** — OCR이 검출한 한 줄 |
| **굵은 마젠타 선** | **영역** — 라인들의 묶음 (근거 지목의 단위) |
| 굵은 선 없이 가는 선만 | **미배정** 낱줄 — 글자는 잡았지만 어느 영역에도 묶이지 않음 |

**색으로 의미를 표시하지 않습니다.** 예전에는 역할별로 색을 달리 칠했는데
(제목=초록/유의사항=빨강 등) 빼기로 했습니다. 이 그림의 용도는 "글자를 어디서 어떻게
잡았는가"이고 그건 좌표로 끝납니다(실측 재현율 100%). 반면 역할은 모델의 의미
판단이라 같은 입력에서도 실행마다 달라질 수 있어(225개 중 6개, 97.3% 일치),
색으로 박으면 **같은 광고인데 실행마다 다른 그림**이 나옵니다.
→ 역할 값 자체는 파싱 결과(JSON)와 검수 화면에 그대로 남아 있습니다.

## 3. 산출물 — 무엇이 나오나

한 문서를 처리하면 **세 개**가 나옵니다. 합치지 않은 이유가 있습니다.

| 산출물 | 내용 | 크기 | 받는 쪽 |
|---|---|---|---|
| `out/json` | 전체 기록 — 영역·라인·bbox·신뢰도·출처·VLM후보 | 9~131 KB | 감사·화면 하이라이트 |
| `out/llm_view` | 정제본 — 영역 → 텍스트 (좌표 제거, 읽는 순서) | 5~23 KB | **RAG 인덱싱** |
| `out/extracted` | 구조화 필드 — 스키마 값 + 근거 | 18~35 KB | **DB 적재** |

**왜 셋인가.** 목적이 서로 충돌하기 때문입니다. 감사에는 *틀린 판독도 남아 있어야*
합니다("OCR은 `1O.1%p`, VLM은 `① 0.1%p`로 읽었다"를 둘 다 보관해야 추적됨). 반대로
LLM 입력에 그 둘을 다 넣으면 판단이 흐려집니다. DB에 넣을 것은 라인이 아니라 **필드**
단위여야 하고요.

### `out/llm_view` — 다음 단계로 넘어가는 정제본

좌표·신뢰도를 걷어내고 **영역 → 텍스트**만 남깁니다. 영역은 **읽는 순서**
(카드 → 위→아래 → 좌→우)로 나열되므로, 섹션 묶음 없이도 화면 흐름이 그대로 문맥이 됩니다.

```jsonc
{
  "document": "[예금성상품-적금] 올원e적금.png",
  "product_group": "예금성", "ad_type": "상세페이지",
  "pages": [{
    "page_number": 1,
    "regions": [
      { "region_id": "p1_r001", "role": "제목", "text": "NH올원e적금" },
      { "region_id": "p1_r002", "role": "제목",
        "text": "연이자율\n최대 연3.6%(기본3.1%)",   // ← 정본 (OCR 그대로)
        "vlm_reading": "최대 연 3.6% (기본 3.1%)",   // ← 후보 (정본 아님)
        "vlm_reading_score": 1.0,
        "vlm_reading_coverage": 0.75,
        "vlm_reading_relation": "head_drop" }
    ],
    "unassigned": "정년드림정약통상)은 제외"     // 영역에 못 묶인 낱줄도 전달
  }]
}
```

**OCR 결과를 정본으로 두고, VLM 판독은 덮어쓰지 않고 후보로만 붙입니다.** VLM 출력은
실행할 때마다 미세하게 달라지는데, 그게 정본을 덮으면 **같은 광고를 두 번 돌렸을 때
심의 대상 문구가 바뀝니다.** 금융광고에 쓸 수 없는 성질이라 구조적으로 분리했습니다.
대신 둘의 관계를 코드가 판정해 딱지를 붙입니다.

| 딱지 | 뜻 |
|---|---|
| `same` | 공백·기호 차이만 — 내용 동일 |
| `head_drop` | 앞 항목명이 생략됨, 값 자체는 온전 (`상품명 NH올원e적금` → `NH올원e적금`) |
| `tail_cut` | VLM 판독의 **뒷부분이 잘림** — 정본이 더 완전 |
| `expanded` | VLM이 **더 많이 읽음** — 회수 가능 |
| `diverged` | 서로 다름 — **사람이 원본을 봐야 함** |

## 4. 샘플별 결과

> 각 샘플마다 **① 파싱이 잡은 박스 그림 → ② 실제 파싱 결과 → ③ 설명** 순서입니다.

### 4-1. 올원e적금 (PNG · 상세페이지)

> 📷 **[이미지] `out/previews/[예금성상품-적금] 올원e적금_p1.jpg`**

| | |
|---|---|
| 입력 | PNG 1122 × 6429px (세로로 매우 긴 모바일 캡처) |
| 분류 | 예금성 / 상세페이지 (파일명 + VLM 일치, 확신도 1.0) |
| 잡은 것 | 영역 50개 · 라인 74개 · 미배정 1개 |
| VLM 후보 부착 | 35개 영역 |
| 스키마 추출 | 135.6초 · 필드 29개 채움 / 8개 미발견 · 근거 커버리지 0.744 |
| 부재 내역 | 미표시 **0** / 해당없음 7 / 판정제외 1 |

```jsonc
{ "region_id": "p1_r001", "role": "제목", "text": "NH올원e적금" },
{ "region_id": "p1_r002", "role": "제목",
  "text": "연이자율\n최대 연3.6%(기본3.1%)",
  "vlm_reading": "최대 연 3.6% (기본 3.1%)", "vlm_reading_relation": "head_drop" },
{ "region_id": "p1_r003", "role": "제목", "text": "상품 안내" },
{ "region_id": "p1_r004", "role": "본문", "text": "상품명 NH올원e적금",
  "vlm_reading": "NH올원e적금", "vlm_reading_relation": "head_drop" }
```

**설명.** 세로 6429px는 한 번에 OCR·VLM에 보낼 수 없어 **글자 밀도를 재서 글자가 없는
줄에서 잘라** 조각으로 나눠 처리합니다(기계적으로 1600px마다 자르면 글자를 반토막 냅니다).
상품 상세 정보가 다 실려 있는 유형이라 필드가 가장 많이 채워졌고(29개),
**미표시가 0건**입니다 — 표시 의무 항목을 다 싣고 있다는 뜻입니다.

### 4-2. NH농협은행-2026_001 (PDF · 이벤트페이지)

> 📷 **[이미지] `out/previews/NH농협은행-2026_001-예금성_p1.jpg`**

| | |
|---|---|
| 입력 | PDF 1페이지 → 720 × 6554px로 렌더 (글자 레이어 없음 → OCR 경로) |
| 분류 | 예금성 / 이벤트페이지 · 세부유형 **입출금(통장·MMDA)** |
| 잡은 것 | 영역 76개 · 라인 198개 · 미배정 13개 |
| VLM 후보 부착 | 56개 영역 |
| 스키마 추출 | 184.8초 · 필드 18개 채움 / 18개 미발견 · 근거 커버리지 0.484 |
| 부재 내역 | 미표시 1 (`rate_change_possibility`) / 해당없음 16 / 판정제외 1 |

```jsonc
{ "region_id": "p1_r000", "role": "본문",
  "text": "우리아이 금융생활 서비스 확대기념 이벤트\n무럭무럭\n우리아이 금융 첫 순간,NH농협은행에서\n12.1.(월)~12.21.(일)",
  "vlm_reading": "…12.1.(월) ~ 12.21.(일)", "vlm_reading_relation": "same" },
{ "region_id": "p1_r004", "role": "제목", "text": "**\n*∗ E V E N T ** ***",
  "vlm_reading": "EVENT", "vlm_reading_relation": "same" },
{ "region_id": "p1_r005", "role": "제목", "text": "우리아이 금융생활 서비스 확대!\n첫 계좌만들고 지원금 받자" }
```

**설명.** 이벤트 페이지는 상품 상세 조건을 애초에 안 싣기 때문에 **해당없음이 16건**으로
많습니다(결함이 아닙니다). 근거 커버리지가 0.484로 낮은 것도 화면 좌측 절반이 앱 목업
이미지(심의 무관)라서입니다. `p1_r004`처럼 장식 타이포를 OCR이 `**\n*∗ E V E N T ** ***`로
읽어도 정본은 그대로 두고 VLM 판독(`EVENT`)을 후보로 붙입니다.

### 4-3. NH농협은행-2026_002 (PNG · 이벤트페이지)

> 📷 **[이미지] `out/previews/NH농협은행-2026_002-예금성_p1.jpg`**

| | |
|---|---|
| 입력 | PNG 720 × 6111px |
| 분류 | 예금성 / 이벤트페이지 · 세부유형 **적금** |
| 잡은 것 | 영역 53개 · 라인 96개 · 미배정 4개 |
| VLM 후보 부착 | 41개 영역 |
| 스키마 추출 | 181.0초 · 필드 24개 채움 / 13개 미발견 · 근거 커버리지 **0.844**(최고) |
| 부재 내역 | 미표시 **4** / 해당없음 9 |

```jsonc
{ "region_id": "p1_r001", "role": "제목", "text": "인생 대박적금이 온대",
  "vlm_reading": "인생 대박적금이 온다!", "vlm_reading_relation": "diverged" },  // ← 사람 확인 필요
{ "region_id": "p1_r002", "role": "제목", "text": "행운의\n777\n이벤트",
  "vlm_reading": "행운의 777 이벤트", "vlm_reading_relation": "same" },
{ "region_id": "p1_r003", "role": "제목", "text": "최고\n[요",
  "vlm_reading": "최고 연", "vlm_reading_relation": "diverged" }   // ← 회전 텍스트, OCR 실패
```

**설명.** 이 문서가 **`diverged` 딱지의 좋은 예**입니다. `p1_r001`은 OCR이 `온대`,
VLM이 `온다!`로 읽어 갈렸고, `p1_r003`은 **회전된 텍스트**라 OCR이 `최고\n[요`까지만
읽었습니다(원본은 `최고 연 7.1%`). 정본을 덮어쓰지 않으므로 둘 다 남아 있고,
검수 화면에서 사람이 원본과 대조할 수 있습니다.

적금 광고인데 **중도해지이율·만기후이율·우대금리 지급조건·예금 종류가 없다**는
미표시 4건이 잡혔습니다. 이건 "사실 관측"이고, 위반인지는 다음 단계가 판정합니다.

### 무엇을 어떻게 재나

| 지표 | 결과 | 재는 방법 |

| 분류 (상품군·광고유형) | **9/9 (100%)** | 골드셋과 문자열 일치 |

| 문장 회수 | **237/242 (98%)** | 골드셋 문장이 파싱 텍스트에 있는지 (정규화 부분일치) |

## 6. 값이 없을 때 — `null` 하나로 두지 않습니다

값 없는 필드를 전부 `not_found`로 두면, 다음 단계에 **걸러야 할 항목 수십 건**이
그대로 넘어갑니다. 그래서 **왜 없는지를 코드로 4분류**합니다(모델 호출 0회 —
규칙이 이미 스키마 메타데이터에 있으니 다시 물어볼 이유가 없습니다).

| kind | 뜻 |
|---|---|
| **미표시** | 표시 의무가 있는데 광고에서 발견되지 않음 — **다음 단계가 확인할 대상** |
| 해당없음 | 이 상품 유형엔 그 개념이 없음 (수시입출식의 '만기 후 이율') |
| 확인필요 | 상품 유형을 못 정해 판단 보류 |
| 판정제외 | 분류·수집용 필드 등 애초에 표시 의무가 아님 |

**실제로 이렇게 갈립니다** (2026-08-03 무캐시 실행):

| 문서 | 세부유형 | 미표시 | 해당없음 | 판정제외 |
|---|---|---:|---:|---:|
| 올원e적금 | 적금 | 0 | 7 | 1 |
| 001 | 입출금(통장·MMDA) | 1 | 16 | 1 |
| 002 | 적금 | **4** | 9 | 0 |
| 003 | 입출금(통장·MMDA) | 2 (+이벤트 1) | 15 | 0 |

값 없는 필드 **56개 중 미표시는 7개**(해당없음 47 + 판정제외 2)이고, 여기에 이벤트
항목 미표시가 1건 더 있습니다. 나머지 **49개를 그대로 넘겼다면** 다음 단계나 담당자가
매 문서마다 십수 건을 손으로 걸러야 했습니다.

> ⚠️ **미표시는 "지적"이 아니라 "사실 관측"입니다.** 우리가 넘기는 것은
> "표시 의무가 있는 항목이 광고 텍스트에서 발견되지 않았다"는 사실이고,
> 위반인지·위험도가 얼마인지는 **규정과 대조해 최종 심의하는 다음 단계
> (RAG/DB 엔진 + 담당자)의 몫**입니다.

## 7. 아직 안 되는 것 / 알려진 한계

### 없는 기능

- **심의 판정 단계가 없습니다.** 미표시 분류와 과장표현 후보 수집까지가 끝이고,
  위험도 산정·수정안 제시·리포트 생성이 없습니다.
- **예금성 상품만 됩니다.** 대출·카드·투자성은 스키마 파일이 없어 확장 대상입니다.
- **시인성(글자크기·색·굵기)·로고 병기는 판정하지 않습니다.** 텍스트 추출만으로는
  잴 수 없는 항목입니다(화면 캡처 PNG에는 물리 글자크기 정보가 없고, 로고는
  이미지입니다). **보류이고 제외가 아닙니다** — 나중에 레이아웃/이미지 분석을
  붙여 구현할 대상으로 근거대장에 남겨 뒀습니다.
- **문자·이메일·배너 광고 전용 항목**(`(광고)` 표시, 수신거부 안내 등)은
  미구현입니다. 지금 샘플이 전부 상세/이벤트페이지라 해당이 없습니다.

### 측정된 한계 (추측이 아니라 실측)

| 항목 | 실측 | 상태 |
|---|---|---|
| 역할 판정 실행 간 변동 | 225개 중 6개(2.7%) | 구조적 — 모델 의미 판단. 정본·좌표는 안 흔들림 |
| 회전 텍스트 OCR 실패 | 002 `최고 연 7.1%` → OCR은 `최고\n[요` | VLM이 후보로 회수. 구조화 필드엔 못 들어감 |
| 그림 속 숫자 | 001 경품 `20,000원`(지폐 목업 안의 숫자) | 파싱은 했으나 필드에 안 담김. `unused_figures`에 기록돼 추적 가능 |
| 카드 경계 판정 | 003 표지 카드의 헤드라인 1개가 실행마다 소속 흔들림 | 각 카드 **내용**은 안 섞임. 알려진 한계로 기록 |
| HWP는 좌표가 없음 | 디지털 텍스트라 정확하지만 화면 하이라이트 불가 | 구조적 |

### 받는 쪽이 반드시 알아야 할 두 가지 ⚠️

**① `region_id`를 영구 키로 쓰면 안 됩니다.**
`p1_r014` 같은 ID는 **생성 순서 라벨**이지 콘텐츠 식별자가 아닙니다. 같은 문서를 두 번
처리하면 같은 ID가 다른 내용을 가리킬 수 있습니다.
→ **문서 처리 버전과 묶어 저장**하고, 버전이 다르면 별개로 취급해야 합니다.

**② 재처리하면 결과가 완전히 같지는 않습니다.**
정본 텍스트와 좌표는 100% 같지만, 역할 판정과 스키마 추출값은 모델 출력이라
`temperature=0`으로도 완전히 고정되지 않습니다(서버측 guided-decoding·배치 비결정성).
→ **"다시 돌리면 같은 결과"를 전제한 설계(멱등 upsert 등)는 깨집니다.**
버전을 누적하고 덮어쓰지 않는 쪽을 제안합니다.
