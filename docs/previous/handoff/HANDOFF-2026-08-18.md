세부 설계는 우리가 제안서로 확정해 나가는 순서다.

### 8-a. 우리가 발신한 것 (회의 결정사항으로 정리해 확인 요청)

- (연동 아키텍처) 커스텀 파서는 진입점(입출력 규격 처리) 역할만 수행하고, 실제 문서 처리(라우팅·OCR·VLM 보정 등)는 별도 에이전트 서비스로 구현하여 파서가 호출하는 구조로 설계를 진행
- (벡터 적재) 데이터 적재는 DAP의 날리지 레이크 파이프라인을 경유하는 원칙을 준수
- (실행 환경) Python 3.11 및 DAP 베이스 이미지 기준으로 의존성을 고정하여 개발
- (패키지 반입) 신규 또는 버전이 상이한 라이브러리는 (필요시) 리스트로 취합하여 전달드리고, 농협 측에서 베이스 이미지 재빌드 방식으로 반영
- (웹 배포) 프론트엔드(WAS)는 컨테이너 이미지 형태로 제공

### 8-b. 우리가 요청한 자료 5건 → 농협 회신 (김원현 과장)

| 요청 | 회신 | 상태 |
|---|---|---|
| ① 커스텀 파서 API 연동 동작 가능 여부 + 요청·응답 규격 정의서 + 샘플 코드 | 파일 첨부 | **받음** — 단 "동작 가능 여부 확인 결과"라는 문장은 없고 첨부로 대신했다. API 연계가 제품 기능임은 readme 가 명시(동기·비동기 둘 다 가능) |
| ② DAP 베이스 이미지 Python 버전 + 전체 라이브러리 리스트 | 파일 첨부 | **절반만** — `2.Package.txt` 는 pip list 284개뿐이고 **파이썬 버전 표기가 없다**(전수 확인). 3.11 의 근거는 우리 회의록뿐 → 문서로 재확인 대상 |
| ③ 대화 이력 적재 규격 가이드 + PostgreSQL 접속 정보(전용 계정·스키마) | 내부 투입 시 제공 | **미제공** |
| ④ DAP 접속 계정 및 접속 가능 여부 | 내부 투입 시 제공 | **미제공 — DAP 접속 없이 설계·개발해야 한다** |
| ⑤ 좌석·출입증, 장비 반입 절차 | 서대문은 오픈이노베이션팀 지원 요청 / 의왕센터 투입 시 신원보증확약서·인력 프로필·증명사진 필요 | 투입 장소 미정 |

### 8-c. 우리가 약속한 산출물 3건 = 다음 할 일

1. 커스텀 파서(진입점) + 에이전트 서비스 + 웹 컨테이너 이미지 구조의 **아키텍처 설계안** —
   "농협 문서 받은 후 진행" 조건이 ①② 로 충족됐다
2. 실행 환경 의존성 확인 후 **필요 패키지 리스트 전달** (테스트 필요·시간 소요를 메일에 명시함)
3. **핵심 모듈 바이너리 패키징 방안** — 내부 검토 후 회신

### 8-d. 자료 분석에서 확인된 것 (2026-08-18, 근거는 전부 자료 실측)

자료 위치: `농협프로젝트\1.awx_custom_parser_example_api` — 파일 17개가 전부다.

- **KL 커스텀 파서 규격**: `POST /parsing`(multipart `src_file` + base64 `option`) → 202 `{uuid, timeout}`
  → KL 이 `GET /parsing/result/{uuid}` 폴링 → zip(`원본명_hrc.jsonl` 필수 + `_hrc.json` + `_img.zip`).
  30초 미만이면 동기(200+zip)도 허용. **우리는 문서당 평균 162.4초·최대 590.1초라 비동기 필수.**
  KL 폴링 timeout 기본값은 3시간이고 우리가 202 응답 body 로 지정한다.
- **출력 포맷에 좌표 칸이 없다**: item 은 text/table/image/h1~h4 뿐, 부가정보는 `cust_meta`
  문자열 15칸(attr 10 + sattr 5). RAG 검색용 포맷이라 bbox·역할·confidence 자리가 없다.
  → 광고물 심의의 근거 좌표는 KL 이 아니라 **PostgreSQL 쪽**으로 가야 한다(설계안에서 우리가 제안).
- **날리지 레이크가 대체하는 것**: nh-ad-compliance 설계의 **Qdrant**(벡터 검색) 자리다
  (`docs/architecture-overview.md:53`). PostgreSQL·MinIO·OpenSearch 는 별개 논의.
- **파이썬 버전 4주체 불일치**: 농협 3.11 / 우리 poc >=3.13(실행 3.13.14) / 사내파서
  document-processor >=3.13 + jpype1 + JVM / nh-ad-compliance >=3.12,<3.13.
  우리 파싱 코드 자체엔 3.12+ 전용 문법·API 흔적 0건(match·PEP695·Path.walk·batched 등)
  → **실행 검증만 남았다.**
- **베이스 이미지에 없는 우리 의존성**(284개 전수 대조): pypdfium2, jpype1, pypdf, python-docx, paddle*.
  있는 것: pillow 12.3.0, requests 2.34.2, pydantic 2.13.4, pyyaml, fastapi, gunicorn, uvicorn.
  paddle 부재는 무해하다(PaddleX 는 원격 HTTP 호출). 이미지·PDF 트랙만이면 **반입 필요는 pypdfium2 1개**.
- **반입 메커니즘 2경로**: whl 을 `flow/whl` 에 두고 `pip install --target=.../custom_libs` + PYTHONPATH
  (setup-application.sh 실측) / 농협 베이스 이미지 재빌드(우리 메일 항목).
- **예제 템플릿 결함 2건**(우리가 쓰면 물릴 자리): `TIMEOUT = os.getenv("TIMEOUT", 600)` 이라
  환경변수를 주면 문자열이 되어 `timeout + 10` 이 TypeError — **타임아웃을 늘리려는 순간 죽는다.**
  그리고 `except` 블록이 미할당 `work_dir` 을 참조할 수 있다.
- **readme ↔ 실제 샘플 불일치 4건**: 문서화 안 된 `item: "break"` 존재 / image `value` 가
  절대경로(문서는 파일명) / image width·height 가 "mm" 라는데 실제는 픽셀로 보임(1102×557) /
  cust_meta 개수 표(1~10)와 본문 예시(`cust_arrt1~5`) 불일치.
- **미해결**: 폐쇄망 안 OCR/LLM 의 실체(readme 는 `parser_info["prop"]` 로 공급자 URL·키를
  주입받는 구조로만 설명, 예시 upstage) / jsonl item 이 곧 청크 단위인지 별도 chunker 가
  다시 자르는지 / `custom_type` 의 `md`·`uh` 뜻 / 에이전트 서비스의 배포 형태.
  **DAP 전체 매뉴얼은 우리 손에 없다** — 진짜 가이드는 폐쇄망 포털 안이고 경로만 `parser_howto.txt` 에 있다.
