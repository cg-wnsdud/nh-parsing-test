                          └────────────────┬────────────────────────┘
                                           │
                 ┌─────────────────────────┼──────────────────────────┐
                 │                         │                          │

                 │                         │                          │
                 │              ① 페이지 triage (triage.py)   ① 사내 파서 디지털 추출

                 │              structured/scan_like/hybrid      텍스트·표 = 정본
                 │                 │        │       │            내장 이미지(BinData)

              ② 캔버스 정규화 (canvas.py)

                            │

                            │
                            ▼
              ④ PP-StructureV3 호출 (paddlex_client.py) — "눈"

              좌표 복원 → 중복 제거(IoU+포함비) → 행 클러스터 읽기순 정렬

                            │
                            ▼

    │            ⑥ VLM 판정 계층 (vlm_judge.py 등) — "뇌"            │
    │                                                               │
    │  ⑥-1 분류: 상품군/광고유형 (파일명 prior 와 합의/충돌 기록)      │
    │  ⑥-2 역할·섹션·묶음 판정: 영역마다 역할(유의사항 등) +          │
    │       섹션(13종 타입·번호) + group_no(카드/패널 묶음)           │
    │       → 비연속 분할(갭>캔버스 15%) → 미배정 라인 좌표 귀속       │
    │  ⑥-3 누락 스윕 (vlm_direct.py): 추출 목록에 없는 화면 문구를     │
    │       VLM 이 직접 전사 (장식 타이포·벡터 텍스트 회수)            │
    │  ⑥-4 필드 추출 — 복수 관측: 전체 1회 + 섹션 크롭 N회            │
    │       → 병합·득표(obs_count) → 값-라인 대조(ocr_backed)         │
    │  ⑥-5 수치 크롭 재확인: 금리/심의필을 고해상 크롭 재판독           │
    │       (숫자 집합 충돌 시에만 교정 — '71%'→'7.1%')               │
    └───────────────────────────┬───────────────────────────────────┘
                                ▼
              ⑦ 필드 정합 judge (field_judge.py)
              중복 병합(코드) → 토큰비율 ocr_score → 신호 충돌 항목만
              텍스트 전용 LLM 심판 (유지/삭제/키교정) — 충돌 없으면 미호출
                                │
                                ▼
              ⑧ 최종 산출물
              out/json/*.json (AdPageIR) ─→ [다음 단계] 심의 검토 엔진

## 단계별 상세

### ① 입력 라우팅 + 페이지 triage — `pipeline.py`, `triage.py`

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 파일 확장자로 트랙 분기. PDF 는 **페이지 단위**로 텍스트 레이어 신뢰 여부 판정 |
| 판정 기준 | 글자 수, U+FFFD(깨진 인코딩) 비율, 정상 문자 비율, 이미지 면적비 |
| 출력 | `structured`(텍스트 레이어 사용) / `scan_like`(OCR 필요) / `hybrid`(병행) — 근거는 `page.triage` 에 기록 |
| 실측 사례 | 003.pdf: p1·p2 는 scan_like(통이미지), p3 는 structured — 한 파일 안에서 페이지별 분기 |
| 실패 시 | 판독 불가 페이지도 조용히 스킵하지 않고 `parse_status="unreadable"` 로 명시 |

### ② 캔버스 정규화 — `canvas.py`

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 모든 입력을 "픽셀 좌표계를 가진 RGB 이미지"로 통일. 이후 모든 좌표는 이 캔버스 기준 |
| 핵심 규칙 | scan_like PDF 는 **내장 래스터의 네이티브 해상도로 렌더** — 업스케일은 정보 없이 OCR 검출만 망가뜨림 (001 실측: 720px 원본을 2000px 렌더 시 문장 매칭 4/22 → 네이티브 렌더로 17/22) |

### ③ 타일링 — `tiling.py`

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 세로 스크롤형 초장신 캔버스(4000px↑)를 1600px 수평 밴드 + 200px 오버랩으로 분할 |
| 이유 | OCR 입력 크기 제한/정확도 — 사용자 질문의 "OCR 을 정확하게 하기 위한 타일링" 이 이 단계 |
| 복원 | 결과 좌표를 원본 캔버스 좌표로 되돌리고, 오버랩 구간 이중 검출은 ⑤에서 제거 |

### ④ PP-StructureV3 — `paddlex_client.py` (역할: "눈")

| 항목 | 내용 |
| --- | --- |
| 하는 일 | 타일 1장당 1회 호출 → ⑴ OCR 라인(텍스트·bbox·신뢰도) ⑵ 레이아웃 블록(doc_title/text/table 등) |
| 안 하는 일 | **의미 해석 없음** — "유의사항인지, 금리인지"는 모른다 (그건 ⑥ VLM의 일) |
| 필수 교정 | 서버 기본값 3개가 광고물을 망가뜨림: `textDetLimitSideLen` 960→2500 (다운스케일 방지), `layoutMergeBboxesMode` large→small (카드 통합 방지), `useTextlineOrientation` off (fine-print 180도 오판 방지) |
| 알려진 한계 | 원문자(①⑦)·위첨자(²) 미인식, 장식 폰트 소수점 소실('7.1%'→'71%') → ⑥-3/⑥-5 가 보완 |

### ⑤ 조립 — `tiling.py`, `regions.py`

| 항목 | 내용 |
| --- | --- |
| 중복 제거 | bbox IoU ≥ 0.5 또는 포함비(겹침/작은쪽) ≥ 0.7 → 신뢰도 높은 쪽만 유지 (타일 경계 조각 제거) |
| 읽기 순서 | 행 클러스터 정렬 — 수직 50% 이상 겹치면 같은 행, 행 안은 좌→우 ('12개월/가입기간' 라벨-값 역전 해소) |
| 영역 구성 | 라인 중심점이 레이아웃 블록 안이면 그 영역(Region)에 배정. 블록 밖 라인은 일단 미배정 |

### ⑥ VLM 판정 계층 (역할: "뇌") — 판단 주체는 전부 VLM, 규칙은 폴백 전용

**⑥-1 분류** — `gemma_client.classify`
파일명 prior(예: "예금성" 포함)와 VLM 화면 판독을 결합, 합의/충돌을 `category_source` 로 기록. VLM 장애 시 파일명 prior 로 무중단 폴백.

**⑥-2 역할·섹션·묶음 판정** — `vlm_judge.judge_region_roles` (페이지당 1회 호출)
영역 목록(발췌 텍스트+위치)+화면 축소본을 주고 영역마다 ⑴ 역할(제목/본문/유의사항/고지문구…) ⑵ 섹션 타입 13종+번호 ⑶ `group_no`(카드/패널 시각 묶음 — SNS 카드형 대응, 묶음 없으면 0) 판정. 코드가 후처리:
- 비연속 분할: 같은 타입인데 수직 갭 > max(300px, 캔버스높이 15%) → 섹션 분리 (토스 고지+심의필 4,000px 병합 사례 해소)
- 미배정 라인 귀속: 정밀 bbox 라인의 중심이 섹션 bbox 안이면 최근접 영역에 흡수 (002 유의사항 불릿 14줄 실측). 근사 bbox 인 스윕 라인은 오귀속 위험 실측으로 제외

**⑥-3 누락 스윕** — `vlm_direct.sweep_missing_lines` (페이지당 1회 호출)
"이미 추출된 텍스트 목록에 없는데 화면에 보이는 문구"를 전사시켜 `source=vlm_sweep` 라인으로 추가. OCR 이 원천적으로 못 잡는 두 부류를 회수: 장식 타이포('행운의 777 이벤트'), 벡터/패스 텍스트(003 p3 제목 — 텍스트 레이어에도 이미지에도 없음). 환각 방지: 기존 텍스트와 정규화 중복이면 폐기.

**⑥-4 필드 추출 — 복수 관측** — `pipeline._extract_fields_multi` + `vlm_judge.extract_fields_vlm`
단일 호출은 서빙 비결정성으로 실행마다 ±5건 흔들림(실측) → 이전 프로젝트의 관측→병합 구조 이식:
- 관측 1: 페이지 전체 라인 + 전체 화면 (기존 경로)
- 관측 2~N: **섹션마다** 그 섹션 라인 + 섹션 bbox 크롭 (컨텍스트가 작아 호출당 안정, 크롭이라 판독도 유리)
- 병합: 같은 key 에서 값이 같거나 포함 관계면 합치고 `obs_count`(득표) 누적, 더 완전한(긴) 값이 대표 — 누락·절단 변동을 합집합으로 흡수
- 검증: 각 값이 참조 라인에 실재하는지 코드 대조(`ocr_backed`) — VLM 은 새 값을 지어낼 수 없음

**⑥-5 수치 크롭 재확인** — `vlm_direct.verify_numeric_fields`
금리/우대금리/심의필번호의 앵커 라인을 고해상 크롭으로 재판독. **숫자 집합이 진짜 충돌할 때만** 교정('최고연71%'→'7.1%'), 부분집합이면 원값 유지(과교정 방지). 깨진 응답은 형식 가드로 거부.

### ⑦ 필드 정합 judge — `field_judge.reconcile_fields`

이전 프로젝트 3단계(관측→병합→judge)의 마지막 단계. 중복 관측 병합(코드) → 토큰 비율 `ocr_score` 산출(여러 줄 걸친 값 구제) → **신호가 충돌하는 항목만** 텍스트 전용 LLM 심판 호출(유지/삭제/키교정 — '0.5%p 가산'이 금리 키로 붙으면 우대금리로 교정). 충돌이 없으면 호출 자체가 없어 평상시 비용 0.

### ⑧ 최종 산출물

| 파일 | 용도 | 소비처 |
| --- | --- | --- |
| `out/json/*.json` (AdPageIR) | **공식 산출물** — 분류+섹션(카드묶음·좌표)+영역·라인(좌표·신뢰도·출처)+필드(검증 플래그)+감사 notes | 심의 검토 엔진 (기준 대조, F-013 하이라이트, 수치 검증) |
| `out/rag/*.json` (RagDocument) | 기준 문서 조항 청크 | 임베딩 → Qdrant/OpenSearch 색인 (기준 DB) |
| `out/previews/*.jpg` | bbox·섹션 오버레이 | 육안 검수 |
| `out/text/*.txt` | 묶음→섹션→영역 순 텍스트 뷰 | 사람 검수 (산출물 아님 — JSON 의 축약 표현) |

JSON 이 큰 이유: 판정 결과 자체는 ~100줄이고 나머지 ~80%는 근거(라인·좌표·신뢰도) — F-013 화면 하이라이트와 감사 추적이 명세 요구라 보존.

## 신뢰성 장치 요약 (조용한 실패 금지 원칙)

| 장치 | 막는 것 |
| --- | --- |
| triage 근거 기록 | 페이지가 왜 OCR/디지털로 갔는지 추적 불가 |
| ocr_backed + ocr_score | VLM 이 지어낸 값(환각) |
| regex_backed | 알려진 표기 패턴과 형태 불일치 (보조 신호, 판정 아님) |
| crop_verified | OCR 수치 오염(원문자 병합, 소수점 소실) |
| obs_count (복수 관측 득표) | 단일 호출의 누락·절단 변동 |
| judge (충돌 시만) | 키 혼동·중복·근거 없는 값 |
| JSON 복구 + 형식 가드 | VLM 서빙 결함(문자열 종료부 손상) — 부록 C-14 |
| 모든 폴백·교정·실패의 notes 기록 | "왜 이번엔 결과가 다르지?"를 추적 불가 |

## 품질 현황과 측정 방법

- 골드셋: `gold/*.yaml` (사용자 직접 작성 232문장 + 필드 + 섹션) ↔ `tools/evaluate.py` 자동 채점 → `out/eval_report.md`
- 파서 선택 근거: `tools/compare_parsers.py` → `out/parser_comparison.md` (document-processor vs kordoc 실측)
- 현재 수준(2026-07-20): 분류 100% / 섹션 84% / 문장 82% / 필드 81~91%(실행 간 변동 폭 — 복수 관측 도입으로 수렴 검증 중)
