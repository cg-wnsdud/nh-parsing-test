# F. 시연 준비와 연동 작업 계획 — "농협 형태로 진행할 게 뭔가"

> **질문**: 파이프라인·스키마 구현은 끝났고, 프로토타입 발표를 위해 입력부터 최종 결과까지
> 시연을 보여준다고 할 때 — 이제 농협 연동 환경과 맞추는 작업만 남은 건가?
>
> **답**: 절반만 맞다. 시연 경로를 실제로 돌려 봤고 **손질 3가지**가 남아 있다.

---

## 1. "연동만 남았나?" — 4갈래로 갈린다

| | 상태 | 근거 |
|---|---|---|
| **파이프라인 로직** | ✅ **끝** | 89건 전수 실행 완료, 3회 실행 대조 |
| **스키마 로직** | ✅ **끝** | 프로토타입 6건 전부 끝단 통과 (예금성·대출성 둘 다) |
| **시연 화면** | 🟡 **손질 3가지** | 아래 2절 — 실제로 돌려서 확인함 |
| **농협 연동** | ⬜ **미착수** | `kl_parser/` 디렉터리 자체가 없음 |
| **시연 범위의 구멍** | ⚠️ **2개** | 아래 3절 — 카드상품·HWP |

**"로직은 끝났다"는 맞다.** 다만 *"입력부터 최종 결과까지 시연"* 을 하려면 **화면**이
필요하고, 그 화면이 지금 바로 뜨는 상태가 아니다.

---

## 2. 시연 경로를 실제로 돌려 봤다

원본은 건드리지 않고 스크래치패드에서 조립해 실행했다.

```
✅ 성공:  5,400KB HTML 생성 / 문서 6개
          미리보기 이미지 10장 내장 · STAGE_3 표 10개 · 미표시 표기 50건
```

**즉 시연 화면은 만들어진다.** 다만 그냥은 안 되고 3가지가 걸린다.

### 그 결과물이 지금 어디 있나

```
nh-ad-review-poc/prototype/demo_review.html      5,739,427 bytes
```

스크래치패드는 세션이 끝나면 사라지므로 **저장소 안으로 옮겨 뒀다.** 브라우저로 바로 열면
프로토타입 6건의 원본 이미지 + 영역 + 파싱 결과 + STAGE_3 표가 한 화면에 있다.
(이미지는 base64 내장이라 외부 리소스를 안 받는다 — 폐쇄망에서도 그대로 열린다.)

`prototype/` 은 `.gitignore` 대상이다. **재생성 가능한 산출물**이라 그게 맞다:

```bash
# json/ previews/ extracted/ 를 담은 폴더를 --src 로 주면 다시 만들어진다 (모델 호출 0회)
PYTHONUTF8=1 .venv/Scripts/python.exe tools/make_review.py --src <폴더> --out <출력.html>
```

### 손질 ① 폴더 구조가 안 맞는다 (제일 큰 걸림돌, 그런데 제일 쉽다)

```
make_review.py 가 찾는 구조          prototype/ 의 실제 구조
  <폴더>/json/*.json                  prototype/out/*.json      ← json/ 하위폴더가 없다
  <폴더>/previews/*.jpg               (없음)                     ← 미리보기가 아예 없다
  <폴더>/extracted/*.json             prototype/extracted/*.json  ✅
```

`prototype/` 은 **손으로 골라 복사해 만든 폴더**라 러너가 만드는 구조가 아니다. 그래서
`--src prototype` 을 주면 *"결과 없음 — 먼저 run_nhdata.py 실행"* 하고 끝난다.

**미리보기는 다시 파싱할 필요가 없다.** `out_new/previews/` 에 89건 전체 97장이 이미 있고,
프로토타입 6건 10페이지가 다 들어 있다:

```
1. 예금성상품(적립식)   1장      5. 예금성상품(입출식)  5장 (5쪽 문서)
1. 대출성상품            1장      23-1. 대출성상품        1장
6-1. 예금성상품(적립식) 1장      7-3. 예금성상품(적립식) 1장
```

→ **파일 복사만. 모델 호출 0회.** (스크래치패드에서 그렇게 해서 성공했다)

**할 일**:
```
prototype/out/json/  하위폴더를 만들어 json 을 옮기거나, --src 가 읽을 별도 폴더를 만든다
prototype/.../previews/  에 out_new/previews 에서 해당 10장 복사
그다음:  make_review.py --src <그 폴더> --out <출력>
```

### 손질 ② 화면에 **틀린 설명문**이 남아 있다

시연 화면 맨 위 파이프라인 설명에 이 문장이 있다:

> `structured`(디지털 텍스트가 정본 → **OCR 생략**)

**[A 문서](A-파이프라인-입력부터-결과까지.md) 3-b 에서 확인한 대로 이건 사실이 아니다.**
지금은 structured 페이지도 StructureV3 를 부르고 route 가 `hybrid` 로 통일된다
(003 p3 전후 실측으로 증명).

**발표 중에 이 문장을 근거로 질문이 들어오면 답이 어긋난다.**

그리고 이게 백로그 항목 *"review.html 설명문 갱신"* 인데, **커밋 안 된 수정이 바로 그 줄을
건드렸으면서 이 부분만 안 고쳤다:**

```diff
-        ("②라우팅", "... <code>hybrid</code>(이미지 비중↑ — 5문서에서 한 번도 안 탐...)
+        ("②라우팅", "... <code>structured</code>(디지털 텍스트가 정본 → OCR 생략) /
+         <code>hybrid</code>(이미지 면적비 50% 이상 → 디지털 텍스트 + 전면 OCR 병행) / ...
                       ↑ hybrid·scan_like 설명은 정확하게 고쳤는데 structured 는 그대로 남았다
```

**고칠 문장 제안**:

> `structured`(텍스트 레이어 정상 — 디지털 텍스트를 정본으로 쓰되 **레이아웃·가로 인식을
> 위해 StructureV3 는 함께 부른다**. 그래서 route 는 `hybrid` 로 통일된다)

### 손질 ③ 커밋 안 된 수정 2건이 시연에 실제로 들어간다

| 미커밋 수정 | 화면에 나타나는 횟수 |
|---|---|
| STAGE_3 제목에 `(스키마는 초안 단계)` 딱지 | **10건** |
| 범람 후보에 `다른 영역 내용을 삼킴 — 근거 채택 금지` 딱지 | **1건** |

둘 다 **시연에 있는 게 맞는 내용**이다(정직한 표시). 다만 커밋 안 된 상태라 다른 세션이
건드리면 사라진다.

## 3. 시연이 보여주는 것 / 못 보여주는 것

**이걸 미리 정해 두지 않으면 발표장에서 질문에 막힌다.**

### ✅ 보여줄 수 있는 것

```
① 광고 파일 6건 (PDF 3 · PNG 1 · JPG 2, 예금성 4 · 대출성 2)
② 원본 위에 상자 그린 그림 — "글자를 어디서 어떻게 잡았나"
③ 파싱 결과 — 영역별 텍스트 + 출처(OCR/디지털) + 신뢰도
④ OCR 정본 vs VLM 후보 대조 + 관계 딱지 (같음/잘림/삼킴 등)
⑤ STAGE_3 결과 — 필드 48칸이 채워진 표, 근거 영역 ID 하이라이트
⑥ 부재 4분류 — "해당없음 / 미표시 / 판정제외 / 확인필요"
⑦ 자기진단 17지표 — 근거 커버리지, 미배정 건수
```

**⑥이 시연의 하이라이트다.** *"값이 15개 없다"* 가 아니라 *"14개는 이 상품에 해당 없고,
지적 후보는 0건"* 이라고 말할 수 있는 것 — 이게 다른 파서와 다른 지점이다.

# 4. 연동 작업 — 지금 상황에서 정확히 무엇인가

## 4-0. 한 문장으로

**지금까지 만든 건 "부엌에서 요리가 되는 것"이고, 연동은 "그 요리를 농협 식당 창구에 내는
배선"이다.** 요리법은 안 바뀐다.

```
[지금]  우리 노트북에서 python 명령으로 실행 → 결과 폴더에 파일이 쌓인다
[연동]  농협 시스템이 HTTP 로 부르면 → 우리가 zip 을 돌려준다
        요리(파싱·스키마)는 그대로. 주문받는 창구만 새로 만든다.
```

## 4-1. 만들 것 — 그림 한 장

```
┌─── 농협 폐쇄망 ────────────────────────────────────────────┐
│                                                            │
│  KL(Knowledge Lake) 이 문서를 우리에게 보낸다               │
│     │                                                      │
│     │  POST /parsing  (파일 + 옵션)                        │
│     ▼                                                      │
│  ┌──────────────────┐   ← ★ 작업 A: 이걸 만든다             │
│  │  진입점 (얇다)    │      · 파일 받아서 번호표 발급         │
│  │  kl_parser/      │      · "접수했다(202)" 즉시 응답      │
│  └──────────────────┘      · 뒤에서 본체에 넘긴다            │
│     │                                                      │
│     │  HTTP 요청                                            │
│     ▼                                                      │
│  ┌──────────────────┐   ← 이미 있다 (우리 코드 그대로)        │
│  │  본체 (두껍다)    │      파싱 → 스키마 추출 → KL형식 변환  │
│  └──────────────────┘                                      │
│     │                    → PP-StructureV3 · Gemma          │
│     ▼                                                      │
│  KL 이 결과를 가져간다                                       │
│     GET /parsing/result/{번호표} → zip 3종                  │
└────────────────────────────────────────────────────────────┘
```

### 왜 둘로 나누나 — 이유가 아주 실용적이다

농협이 준 패키지 목록 285개를 직접 조회했다:

```
requests 2.34.2 ✅   pillow 12.3.0 ✅   pydantic 2.13.4 ✅   numpy 2.4.6 ✅
pypdfium2 ❌ 없음     jpype1 ❌ 없음
```

그리고 **사내 HWP 파서가 Python 3.13 + 자바를 요구하는데 농협 환경은 3.11 기준**이다.

| | 한 덩어리로 넣으면 | **둘로 나누면** |
|---|---|---|
| 진입점에 필요한 라이브러리 | pypdfium2 + JVM + 사내파서 전부 | **`requests` 하나** |
| 농협에 반입 요청할 것 | 3건 + 자바 런타임 | **0건** (이미 있음) |
| Python 3.11 제약 | 우리 코드 전부가 3.11 에서 돌아야 함 | **진입점만.** 본체는 3.13 자유 |

→ **나누는 순간 3.11 vs 3.13 충돌이 자동으로 풀린다.**

---

## 4-2. 작업 5개 — 각각 무엇을 하는 것인가

### 작업 A. 진입점 만들기 (`kl_parser/`) — 가장 큰 것, 그래도 얇다

**농협이 준 예제 `main.py` 를 고쳐 쓰는 일**이다. 새로 설계하는 게 아니다.

```
kl_parser/                                  ← 만들 것
  main.py              POST /parsing → 202 {uuid, timeout}
                       GET  /parsing/result/{uuid} → zip
  requirements.txt     requests 만 (농협 이미지에 2.34.2 이미 있음 → 반입 0건)
  Dockerfile           농협 DAP 베이스 이미지 기준
```

**무슨 코드냐 하면 이 정도다:**

```
POST /parsing 이 오면:
   1. 파일을 저장한다
   2. 번호표(uuid)를 만든다
   3. "PARSING" 이라고 상태 파일에 적는다
   4. 뒤에서 본체에 HTTP 로 던진다
   5. 곧바로 202 + {번호표, 타임아웃} 을 돌려준다     ← 여기서 기다리지 않는다

GET /parsing/result/{번호표} 가 오면:
   · 아직 중이면    → {"status":"PARSING"}
   · 끝났으면      → zip 3종 (_hrc.jsonl + _hrc.json + _img.zip)
   · 실패했으면    → {"status":"ERROR", "message":...}
```

**왜 즉시 응답하고 기다리지 않나**: 우리 처리 시간이 **문서당 평균 162초, 최대 590초**다.
HTTP 연결을 그만큼 붙잡고 있으면 중간 장비가 끊는다. 그래서 *"접수했다"* 만 먼저 주고 나중에
찾아가게 한다. (농협 규격도 30초 넘으면 이 방식을 권한다)

**같이 고쳐야 할 농협 예제 결함 6건** — 코드로 다 확인했다
([D 문서](D-농협-자료와-연동-규격.md) 5절 상세):

| # | 무엇이 잘못됐나 | 무슨 일이 나나 |
|---|---|---|
| 1 | `TIMEOUT = os.getenv("TIMEOUT", 600)` | 타임아웃을 늘리려고 환경변수를 주는 순간 **문자열이 되어 죽는다.** 기본 600초는 우리 최대 590초와 마진 10초뿐 |
| 2 | `except` 안에서 `work_dir` 참조 | 앞부분에서 오류가 나면 **오류 처리 중에 또 오류** |
| 3 | `img_zip_file` 이 특정 분기 안에서만 만들어짐 | 결과 파일이 없으면 **이름 없는 변수 참조로 죽는다** |
| 4 | `os.listdir(img_dir)` 무조건 호출 | 이미지 폴더가 없으면 예외 |
| 5 | `option` 을 base64 풀지 않음 (`options = {}`) | 농협이 보내는 문서 제목·카테고리를 **안 쓰고 버린다** |
| 6 | `_hrc.json`(문서정보)을 만들지 않음 | 규격이 요구하는 3종 중 1종 누락 — **우리 `kl_export` 는 이미 3종 다 만든다** |

> 이 예제는 완성품이 아니라 골격이다. 코드에 `# TODO: M A I N: 파싱` 이라고 적혀 있고,
> 하드코딩된 쿠버네티스 샘플 텍스트(`"(이것은 하드코딩된 응답입니다)"`)가 들어 있다.

### 작업 B. 규격 검사기 — "우리가 낸 파일이 규격을 지켰나"를 기계로 본다

지금은 사람이 눈으로 본다. 검사할 항목:

```
zip 안에 3종이 다 있나 · 파일명이 <원본명>_hrc.jsonl 인가 (확장자를 떼지 않는다)
각 줄이 유효한 JSON 인가 · item 이 7종(text/table/image/h1~h4) 안인가
value 가 빈 값 아닌가 · table 의 value 가 <table> 로 시작하나
image 에 4키(title/width/height/ratio) 가 다 있나
cust_meta 이름이 cust_attr1~5 / cust_sattr1~5 안인가
```

**절반은 이미 있다** — `test_kl_export.py` 15개. 없는 건 **최종 zip** 검사다.

### 작업 C. 왕복 시험 — 농협이 준 스크립트를 그대로 쓴다

### 작업 E. 미확정 대장 — 방문의 실질 산출물

**"우리가 결정할 수 없어서 물어봐야 하는 것"** 을 한 문서에 모으는 일이다. 지금은 **코드
주석에 흩어져 있다.** 초안은 [E 문서](E-남은-일과-정리-후보.md) 3절 "방문해야만 확인되는 것"
목록이다.

```
🔴 KL 검색(조회) API 규격        ← 받은 자료 17개에 적재(쓰기) 규격만 있다.
                                   조회를 못 하면 심의 경로를 못 만든다
🔴 입출금 통장 표시의무 5건        ← 지금 "만기 개념 없어 해당없음" 으로 처리 중인데
                                   조문 근거 없는 우리 해석. 준법팀 확인 필요
🔴 규정 청크에 checklist_ref 붙이는 방법  ← 자리는 예약했는데 채울 방법이 없다
🟡 cust_attr6~10 이 실제로 저장되나       ← 규격서 본문 5개 / 표 10개로 불일치
🟡 image width·height 단위 (mm ↔ 픽셀)   ← 규격서는 mm, 정답 샘플은 픽셀
🟡 item "break" 의 뜻                    ← 정답 샘플에 있는데 규격서에 없다
🟡 jsonl 한 줄이 곧 청크인가              ← KL 이 다시 자르는지 불명
🟡 custom_type 의 md·uh 뜻
🟡 폐쇄망 OCR·VLM 실체
⬜ Python 버전 문서 근거                  ← 2.Package.txt 에 파이썬 버전 표기가 없다
```

## 4-4. 순서 — 왜 이 순서인가

```
E 대장  →  A 진입점  →  B 검사기  →  C 왕복  →  D 환경
```

**E 를 먼저 하는 이유**: A 를 만들 때 *"`option` 을 쓸까?"*, *"`cust_attr6~10` 을 쓸까?"* 같은
미확정 항목이 설계에 영향을 준다. 대장을 먼저 쓰면 **무엇을 확정 못 한 채 만드는지 알고
만든다.** A 를 먼저 하면 그 판단이 코드에 조용히 박혀 나중에 왜 그렇게 했는지 아무도 모른다.

**D 를 마지막에 두는 이유**: A~C 가 끝나야 "무엇을 3.11 에서 돌려 봐야 하는지"가 확정된다.

## 4-5. 농협 없이는 못 하는 것 — 미리 알아두기

```
⬜ DAP 접속 계정          → "내부 투입 시 제공"  = 지금 접속 불가
⬜ PostgreSQL 접속 정보    → 같음
⬜ KL 검색 API 규격        → 자료에 없음. 요청해야 한다
⬜ 폐쇄망 안 OCR·VLM 실체  → 미정 (우리 코드는 환경변수만 바꾸면 교체됨)
```

**즉 "농협 시스템에 실제로 꽂아서 돌려 보는 것"은 방문 후다.** 방문 전에 할 수 있는 것은
*"규격대로 만들고, 우리 쪽에서 왕복이 되는 것까지 확인"* 이다.

### 모델 교체 준비 상태 (참고)

우리 코드는 **환경변수만 바꾸면 교체된다**
([config.py](../../src/nh_parsing/config.py)): `PADDLEX_URL`, `GEMMA_URL`, `GEMMA_MODEL`
전부 `os.environ.get`. 단 성질이 다르다:

| | 코드 변경량 | 대체 모델 요건 |
|---|---|---|
| **VLM** (Gemma) | 거의 없음 (URL·모델명) | OpenAI 호환 + **이미지 입력** + **strict json_schema**. 품질 재측정 필수 |
| **OCR** (PaddleX) | 어댑터 한 파일(187줄) | **레이아웃 블록 + 읽기순서**를 줘야 한다. 글자 줄만 주면 **영역·역할·카드분할이 사라진다** = 재설계 |

## 5. 정리 — 지금 할 수 있는 일 3갈래

| | 무엇 | 걸리는 일 | 왜 지금 |
|---|---|---|---|
| **① 시연 준비 마무리** | 폴더 재배치 + 미리보기 복사 + **틀린 설명문 1건 수정** + 미커밋 2건 커밋 | 짧음. **모델 호출 0회** | 발표가 가까우면 1순위. 성공을 이미 확인함 |
| **② 미확정 대장 작성 (작업 E)** | 코드 주석에 흩어진 현장 확인 항목 + 4-2E 의 10개를 한 문서로 | 짧음 | 연동 작업의 선행. **KL 검색 API 요청**이 여기서 나온다 |
| **③ 진입점 착수 (작업 A~D)** | 4-2 의 5개 작업 | 가장 큼 | 농협 승인 없이 우리만으로 끝낼 수 있는 마지막 덩어리 |

**추천은 ① → ② → ③ 이다.** 이유: ①은 짧고 발표에 직결되며, 무엇보다 **화면에 틀린 설명문이
남아 있는 상태로 발표하면 그 자리에서 신뢰를 잃는다.** ②는 ③의 선행이고 방문 준비물이다.

### 진행 전 확인이 필요한 것 2가지

1. **발표에 규정문서 트랙(RAG/KL)도 넣을 것인가?**
   지금 시연 화면은 **광고물 전용**이다. 규정문서는 `_hrc.jsonl` 파일을 열어 보이는 정도밖에
   안 된다 — 화면이 필요하면 별도 작업이다.
2. **카드상품(22%)을 시연에서 어떻게 다룰 것인가?**
   `parse_only` 2건이 준비돼 있으니 *"파싱은 되고 스키마는 다음 단계"* 로 정직하게 보여줄 수
   있는데, 아예 안 보여주는 선택도 가능하다. 이건 발표 전략이라 우리가 정할 일이 아니다.
