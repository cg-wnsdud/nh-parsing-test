## 이 프로젝트가 무엇을 하는가 — 30초

```
금융상품 광고물(PDF·PNG·JPG·HWP)이 들어온다
    ↓  ① 파싱          "무슨 글자가 화면 어디에 있나"            ← A
    ↓  ② 스키마 추출    "규정이 요구하는 항목을 어떻게 표시했나"   ← B, C
    ↓  ③ 넘김           심의 담당자·RAG/DB 담당자에게            ← C, D
심의 판정은 우리가 하지 않는다. 우리는 "미표시"라는 관측을 넘기고
"위반"이라는 결론은 다음 단계가 낸다.
```

**두 트랙이 있다** (이게 제일 헷갈리는 부분 — D 참조):

| | 트랙 A 규정문서 | 트랙 B 광고물 |
|---|---|---|
| 예 | `(2023년)예금성상품 광고시 준수사항.hwp` | `1. 대출성상품.pdf` |
| 역할 | **검색당하는 쪽** = 지식 | **검색하는 쪽** = 질문 |
| 좌표 필요? | 아니오 | **예 — 본질** |
| 농협 KL 에 넣나 | **넣는다** | **안 넣는다** |

## 이 프로젝트에서 지켜온 규율 6개

이 규율들은 전부 **실제로 틀렸던 경험**에서 나왔다. 각 문서에 그 사례가 적혀 있다.

1. **원본으로 검증한다** — JSON·좌표만 보고 결론 내지 않는다. 필요하면 원본 이미지를 눈으로 대조한다. 이 원칙으로 골드(정답지)의 오류를 잡은 적이 있다.
2. **지표는 2층으로 읽는다** — `source` 가 `ocr`/`digital` 인 것은 같은 입력이면 항상 같다(단일 수치). `vlm_sweep`·`vlm_reading` 은 실행마다 다르다(범위). 섞어 비교하면 오판한다. → A-③
3. **과적합 휴리스틱 금지** — 판단 주체는 AI(VLM)이고 정규식·규칙은 폴백·보조 신호로만. 특정 샘플에 맞춘 규칙을 만들지 않는다.
4. **`verbatim` 필드는 다듬지 않는다** — 광고 문구를 정규화하면 표기 불일치라는 심의 지적거리가 사라진다(`1,000명`/`1,000팀` 이 합쳐져 소멸한 전례). → B-4
5. **착수 전에 완료 기준을 숫자로 정하고, 안 할 것도 명시한다.** → F-4
6. **원인을 추측으로 짚지 않는다** — 지표가 흔들리면 코드를 고치기 전에 원문·표본부터 확보한다. 이걸 안 지켜 두 번 틀린 기록이 있다.

## ⚠️ 이름이 같아서 헷갈리는 것 5쌍

문서를 읽다 막히면 대부분 이 다섯 중 하나다. **이름이 비슷한데 완전히 다른 것들이다.**

### ① "커버리지" — 2종이 있고 서로 무관하다

| | **체크리스트 커버리지** | **근거 커버리지 (런타임 `coverage`)** |
|---|---|---|
| 언제 재나 | **스키마를 설계할 때 1회** | **문서를 처리할 때마다** |
| 분모 | 정본 체크리스트 **97항목** | 그 문서의 **영역(region) 수** |
| 분자 | 스키마가 `checklist_ref` 로 가리킨 ID | 필드가 `evidence` 로 인용한 영역 |
| 값 예 | 71/73 = **97.3%** (업무광고 제외) | `region_coverage: 0.776` (38/49) |
| 무슨 뜻 | **규정을 빠뜨렸나** | **광고를 빠뜨렸나** |
| 어디 | [B §5](B-스키마-구조와-근거.md#5-근거--무엇이-정본인가-) | [C §5](C-최종-산출물과-다음-단계.md#5-coverage--골드정답지-없이-재는-17지표) |

> 둘 다 100% 가 목표가 아니다. 체크리스트 커버리지의 미커버 2건은 **"그 외 사유" 자유기술
> 항목**이라 필드로 만들 수 없고, 근거 커버리지의 미인용 영역은 **장식·이미지 캡션**일 수 있다.

### ② "체크리스트" — 파일이 3종이다

| 파일 | 만든 곳 | 규모 | ID | 지위 |
|---|---|---|---|---|
| **심의사례 …준법감시부 1.xlsx** `[체크리스트]` | **농협 준법감시부** | **97** | `DEP-`/`LOAN-`/`BIZ-` | ⭐ **정본** |
| `260713_2_NH_광고심의_체크리스트.xlsx` (v12) | 우리 | 6시트 축기반 | — | 분류축 근거 |
| `NH_광고심의_규칙리스트_최종.xlsx` `[체크리스트]` | 사내 연구소 | 339 | `CL001~` | 참고(임시) |

`checklist_ref` 가 가리키는 건 **첫 줄 하나뿐**이다. → [B §5-A](B-스키마-구조와-근거.md#5-a-사내-연구소-자료규칙리스트는-무엇이고-참고용이-정확히-무슨-뜻인가)

### ③ `구분` vs `obligation` — 어휘가 다르다

```
정본의 '구분'        포함사항 · 금지사항 · 형식 · 전자적전송매체 · 공동광고 · 기타
우리 obligation      필수 · 권장 · 관측 · 수집 · 분류 · 절차
```

**베낀 게 아니라 2축(무엇을 점검 × 얼마나 강제)이 합쳐진 값이다.**
→ [B-③](B-스키마-구조와-근거.md#b-③-obligation표시-의무-성격은-어떻게-판단하나)

### ④ `observation_fields`(키) vs `obligation: 관측`(값)

정확히 같은 20개 항목에 붙어 있지만 역할이 반대다 — **하나는 입력 형태, 하나는 출력 취급**.
→ [B §7-A](B-스키마-구조와-근거.md#7-a-observation_fields-는-왜-따로-있나--없어도-되는-것-아닌가)

### ⑤ `parse_route` vs `page.triage.verdict`

`parse_route` 는 **문서 단위**(digital/ocr/hybrid), `verdict` 는 **페이지 단위**
(structured/scan_like/hybrid). 값 이름이 겹쳐 보이지만 다른 층이다. → [A §2](A-파이프라인-입력부터-결과까지.md)
