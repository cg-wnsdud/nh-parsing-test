# K. 커스텀 파서 구현 공유 + 질문

> **누구에게** 지민대리님
> **무엇을** 농협이 준 예제 API(`1.awx_custom_parser_example_api`)에 맞춰 우리 파싱
> 파이프라인을 커스텀 파서로 붙였습니다. 파일을 넣으면 어떤 호출을 거쳐 무엇이
> 나오는지, 그리고 우리가 결정한 규격과 여쭙고 싶은 것을 정리했습니다.
> **작성** 2026-08-24 · 아래 수치는 전부 실제 왕복 시험 결과입니다.

## 1. 한 장 요약

```
                    ┌──────────────────────────────────────────┐
   농협 KL Admin     │  Parser 관리 > Custom 파서 (우리 슬롯)     │
   또는 심의 엔진  ──▶│  POST /parsing        규정문서            │
                    │  POST /ad/parsing     광고물              │
                    └───────────────┬──────────────────────────┘
                                    │ 즉시 202 + 작업번호(uuid)
                                    ▼
                     ┌──────────────────────────────────────┐
                     │  우리 파싱 파이프라인 (뒤에서 계속 돈다)│
                     │   PDF/이미지 → PaddleX OCR·레이아웃   │
                     │   → Gemma(VLM) 판독·판정 → 결과 조립  │
                     └───────────────┬──────────────────────┘
                                     │
   GET /parsing/result/{uuid} ────────┤  PARSING 이면 {"status":"PARSING"}
                                     └▶ 끝났으면 결과 zip
```

**핵심은 두 번 부른다는 것입니다.** 파싱이 오래 걸리니(광고 최대 627초) 첫 호출은
번호표만 주고 끊고, 두 번째 호출로 결과를 찾아갑니다. 농협 규격서
(`parser_howto.txt`)가 정한 방식 그대로입니다.

## 2. 규정문서를 넣으면 — `POST /parsing`

### 호출

```
POST /parsing
  file    : (2023년)예금성상품 광고시 준수사항.hwp
  option  : {"parseImage": true}
→ 202  {"uuid": "a3f1…"}
```

### 중간에 무슨 일이

```
1. 문서 본문 추출        HWP/PDF 원문 → 조문 단위로 쪼갠다
2. 제목 계층 판별        제1장 → 제1조 → 1. → 가.   = h1~h4
3. 표는 표로             HTML 문자열로 담는다
4. 이미지 추출 + VLM 캡션  ★ 그림에 무엇이 있는지 글로 적어 함께 색인한다
5. _hrc.jsonl 조립       농협 규격 형식으로
```

**4번이 우리가 더한 부분입니다.** 규정문서에는 "이런 광고는 안 된다"를 그림으로 보여주는
사례가 많은데, 그림은 검색이 안 됩니다. 그래서 VLM 이 읽어 글로 만들어 붙입니다:

> `[이미지 사례 odl-img-p59]` 금융상품 광고에서 과장될 수 있는 '90초'라는 소요 시간(빨간 원)과
> '바로 입금'(빨간 박스)이라는 즉시성을 강조한 사례를 보여줍니다.
> **이미지 내 텍스트:** 내 통장에 비상금이 / 90초면 뚝딱 / 최대한도 3백만원 …

### 최종 출력 (zip)

```
{원본명}_hrc.jsonl    ← 청크 목록. KL 이 이걸 읽어 벡터DB에 넣는다
{원본명}_hrc.json     ← 같은 내용의 json
{원본명}_img.zip      ← 추출 이미지들
```

### 실측

| 파일 | 결과 | 청크 | 소요 |
|---|---|---|---|
| (2023년)예금성상품 광고시 준수사항.hwp | 202 → zip 3종 | 82행 | **4초** |
| (2025년)대출성 상품 광고시 준수사항.pdf | 202 → zip 3종 | 65행 | **44초** |

## 3. 광고물을 넣으면 — `POST /ad/parsing`

### 왜 창구를 따로 뒀나

| | 규정문서 | 광고물 |
|---|---|---|
| 역할 | **검색당하는 쪽** = 지식 | **검색하는 쪽** = 심의 대상 |
| 좌표가 필요? | 아니오 | **예 — 본질** |
| KL 에 넣나 | 넣는다 | **안 넣는다** |

광고 심의는 *"이 지적의 근거가 원본 어디인가"* 를 화면에 표시해야 합니다. 그런데
**농협 `_hrc.jsonl` 규격에 좌표를 담을 칸이 없습니다** (`item` 유형은 `text`·`table`·
`image`·`h1~h4`, 부가정보는 `cust_meta` 문자열 key-value뿐). 그래서 광고물은 좌표가
살아 있는 별도 형식으로 냅니다. → **§5 질문 ③**

### 중간에 무슨 일이

```
1. 분류        파일명 + VLM 으로 상품군 판정 (예금성/대출성/카드)
               + 고유 상품명이 광고에 적혀 있나 (노출/미노출)
2. 템플릿 선택  위 두 값으로 라벨 사전 12종 중 하나  예) '예금성상품-적립식'
3. 파싱        PaddleX 로 글자·좌표·레이아웃 영역
4. 표 구조      ★ 표는 행·열 격자로 (2026-08-24 추가)
5. VLM 판독     영역 역할 판정 + 놓친 장식 문구 회수 + 저신뢰 글자 재판독
6. 라벨링       템플릿 항목을 영역·줄에 붙인다
7. 통합 JSON    좌표 + 라벨을 한 파일로
```

**4번(표)이 방금 더한 것입니다.** 전에는 표가 줄로 흩어져 우대조건과 우대금리의 짝이
소실됐습니다. 지금은 이렇게 나옵니다 (`2. 예금성상품(적립식).pdf` 실제 결과):

```
①당행 첫 거래 고객 우대주1)                              │ 3.8
②당행 첫 거래 고객이 아니면서, 상품 가입일 포함 최근 6개월… │ 1.0
③가입 월부터 만기 전월 말까지 급여실적 3개월 이상 우대주3)  │ 0.5
④NH올원뱅크를 통해 해당 상품 가입 시 우대                 │ 0.5
```

### 최종 출력 (zip)

```
{원본명}_parsed.json    ← 통합 JSON (좌표 + 템플릿 라벨 + 표 격자)
ad_summary.json        ← 분류·템플릿·집계 요약
{원본명}_img.zip        ← 쪽 원본 이미지
```

통합 JSON 한 줄은 이렇게 생겼습니다:

```json
{
  "line_ref": "p1/p1_r010/L03",
  "text": "최고 연 7.1%",
  "bbox": [66, 1742, 988, 1868],      ← 원본 어디인지
  "source": "ocr",                    ← 정본인가 VLM 후보인가
  "confidence": 0.9997,
  "labels": [{"gubun": "우대금리", "phrase_id": "P014", "how": "한줄내"}]
}
```

### 실측

| 파일 | 템플릿 판정 | 영역 | 줄 | 라벨 닿음 | 표 격자 | 왕복 소요 |
|---|---|---|---|---|---|---|
| [예금성상품-적금] 올원e적금.png | 예금성상품-적립식 | 50 | 78 | 63 | — | 198초 |
| NH농협은행-2026_002-예금성.png | 예금성상품-적립식 | 53 | 97 | 39 | — | 204초 |
| 2. 예금성상품(적립식).pdf | 예금성상품-적립식 | 20 | 73 | 54 | **5행 2열** | 153초 |
| 13. 대출성상품.pdf | 대출성상품-상품명 노출 | 33 | 70 | 56 | **2행 3열** | **627초** |
| 13. 카드상품.jpg | 카드상품-상품명 미노출 | 12 | 55 | 20 | — | 72초 |

> 영역·줄·라벨은 **현재 코드**(2026-08-24, 표·순서 반영) 기준입니다. 왕복 소요는 진입점을
> 거친 실제 왕복 시험값입니다. 두 수치는 다른 실행이라 시간만 따로 보셔야 합니다 —
> 재실행 시에는 VLM 응답 캐시를 써서 3~198초로 줄었습니다(개발 도구, 운영에는 끕니다).
> **VLM 층은 실행마다 조금씩 흔들립니다**(회수하는 장식 문구가 달라짐). OCR·디지털
> 텍스트(정본층)는 같은 입력이면 **줄·좌표까지 100% 재현**됩니다 — 5건 전부 확인했습니다.

> **"라벨 닿음"이 낮은 건 결함이 아닙니다.** 카드 광고의 `'현금 걱정 없는 캐디피결제
> 11만원 할인 이벤트'` 같은 헤드라인은 템플릿에 해당 항목이 없어서 라벨이 안 붙습니다.
> 우리 목표는 **모든 글자를 좌표와 함께 보존하는 것**이고, 애매한 것에 억지로 라벨을
> 붙이면 없는 지적을 만듭니다. 라벨이 없어도 글자는 전부 실립니다.

## 4. 규격을 지키는지 어떻게 확인했나

문서로만 "맞췄습니다"라고 하지 않으려고 검사 코드를 두었습니다.

| 검사 | 무엇을 보나 | 소요 |
|---|---|---|
| `spec_check.py` | `_hrc.jsonl` 이 규격서를 지키나 (item 유형·파일명·`cust_meta` 개수·표 HTML) | 즉시 |
| `boot_check.py` | 농협 배포 방식(`cd app_custom_parser && gunicorn main:app`)으로 뜨나 · 파싱 실패가 `200 + ERROR` 인가 | 1초 |
| `roundtrip.py` / `roundtrip_ad.py` | 실제로 202 → 폴링 → zip 이 되나 | 4~627초 |

`boot_check` 는 **일부러 코드를 되돌려 검사가 정말 잡는지도 확인했습니다** (되돌리면 NG).

이 과정에서 우리 코드의 규격 위반 2건을 찾아 고쳤습니다:
- 파싱 실패에 `500` 을 보내고 있었습니다 (규격은 `200 + {"status":"ERROR"}`)
- `gunicorn main:app` 형태로는 **뜨지도 않았습니다** (상대 import 구조 문제)

## 5. 여쭙고 싶은 것

### 규격 — 우리가 정했습니다. 이렇게 가면 될까요?

규격서(`readme.md`)와 정답 샘플(`out_sample_hrc.jsonl`)이 서로 다른 대목이 여러 곳
있었습니다. 정답 샘플은 예시로 보고 **규격서 본문을 따르는 쪽으로 우리가 정했습니다.**

| 항목 | 규격서 | 정답 샘플 | 우리 결정 |
|---|---|---|---|
| `item` 유형 `break` | 없음 | 있음 | 안 씁니다 (필요하면 알려 주세요) |
| `cust_attr` 개수 | 본문 5 / 표 10 | — | **5개**까지만 |
| `image` 크기 단위 | mm | PDF는 pt, HWP는 cm | **mm** |
| `image` 의 `value` | 파일명 | 절대경로 | **파일명만** |
| `page_info` 단위 | 명시 없음 | PDF pt / HWP cm | PDF는 pt 실측, HWP는 **빈 배열** |
| 파싱 실패 응답 | **200+ERROR** | 예제 코드는 500 | **200+ERROR** (규격서 본문) |

### 요구 — 이건 농협 쪽 설정 변경이 필요합니다

| # | 무엇 | 왜 |
|---|---|---|
| ① | **`gunicorn timeout` 을 1800초 이상**으로 | 예제 `gunicorn_config.py` 는 `timeout=180`. 우리 광고 파싱이 **627초** 걸립니다(대부분 VLM 대기). 180초면 결과가 나오기 전에 일꾼이 죽습니다 |
| ② | 파서 신고 `TIMEOUT` **1800초** | 같은 이유. 규격 기본값이 3시간이니 1800은 그보다 보수적입니다 |
| ③ | **`item` 에 좌표 칸**을 열어 주실 수 있나요? 또는 `cust_attr` 를 좌표 용도로 써도 되나요? | 지금은 광고물을 KL 밖에 따로 두고 있습니다(§3). 좌표를 담을 수 있으면 창구를 하나로 합칠 수 있습니다. `cust_attr` 는 조회 전용이라 벡터를 오염시키지 않아 후보로 봤습니다 |
| ④ | `cust_attr6~10` 이 실제로 저장되나요? | 되면 좌표·역할을 더 담을 수 있습니다 |

### 아직 못 받은 것

| # | 무엇 | 지금 상태 |
|---|---|---|
| ⑤ | **KL 검색(조회) API 규격** | 자료 자체를 받지 못했습니다. 미구현 |
| ⑥ | PostgreSQL 접속 정보 | "내부 투입 시 제공" 상태. 테이블 설계는 마쳐 뒀습니다 |
| ⑦ | `gunicorn_config.py` 원본 | 사내 모듈 `import dlp` 를 쓰는데 우리 PC 에서 실행이 안 됩니다 |
| ⑧ | 폐쇄망 접속 · KL 슬롯 등록 | 미접속 |

### 방향 — 어떻게 잡아야 할지 판단이 안 서는 것

**1. 광고물 트랙을 KL 안으로 넣을까요, 밖에 둘까요?**

지금은 밖입니다(좌표 칸이 없어서). 요구 ③이 되면 안으로 합칠 수 있는데, **KL 은
검색용 지식 창고**이고 광고물은 검색당할 대상이 아닙니다. 그래서 규격상 가능해져도
**넣는 게 맞는지는 별개 판단**이라고 봅니다.

**2. 심의 판정은 어디서 하나요?**

우리는 지금 *"이 항목이 이 위치에 이렇게 표시돼 있다 / 안 보인다"* 는 **관측**만 냅니다.
*"그래서 위반이다"* 는 결론은 내지 않습니다. 그 판정을 하는 쪽이 농협 시스템인지, 우리가
만들어야 하는지에 따라 다음 작업이 완전히 달라집니다.

**3. 광고 파싱 결과 저장소는 누가 만드나요?**

문서당 162초(89건 평균)라 재파싱이 비쌉니다. PostgreSQL 테이블 설계는 해뒀는데
(정본 JSONB 1칸 + 질의용 색인 테이블 6개), **만드는 주체와 위치**를 못 정했습니다.
농협 DAP 쪽에도 저장소가 있다면 어느 쪽이 정본인지도요.

**4. 다음 마일스톤을 무엇으로 잡을까요?**

지금 확인한 것은 **"농협 규격 문서와 예제 코드 기준으로 프로토콜을 맞게 지킨다"** 입니다.
**"농협 실제 인프라에서 돈다"** 는 확인할 방법이 없습니다(폐쇄망 미접속). 후보:

```
(가) 폐쇄망 접속 + 실제 gunicorn 기동 시험   ← 가장 큰 미확인 덩어리
(나) KL 검색 API 규격 받아서 조회 구현
(다) 표·좌표 등 파싱 품질 계속 올리기
(라) 심의 판정 층 설계
```

## 6. 지금 시연 가능한 것 / 불가능한 것

| | 가능? |
|---|---|
| 우리 PC 에서 농협 규격대로 왕복(202 → 폴링 → zip) | **가능** — 7건 실측 완료 |
| 규정문서가 `_hrc.jsonl` 로 바뀌고 이미지에 VLM 캡션이 붙는 것 | **가능** |
| 광고물이 좌표 + 템플릿 라벨 + 표 격자 JSON 으로 나오는 것 | **가능** |
| 규격 준수를 검사 코드로 증명 | **가능** |
| **농협 실제 KL 에 꽂아서 도는 것** | **불가** — ⑤~⑧ 미확인 |
