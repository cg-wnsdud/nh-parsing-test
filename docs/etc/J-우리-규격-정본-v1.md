# J. 우리 규격 정본 v1 — 우리가 정하고, 농협에 확인 요청한다

> **작성** 2026-08-24
>
> **이 문서가 왜 새로 필요한가.** 지금까지 우리는 농협 자료(규격서 `readme.md` +
> 정답 샘플 `out_sample_hrc.jsonl`)가 서로 어긋나는 대목을 **"확인 대기"로 두고
> 멈춰 있었다.** 그 목록이 네 곳에 흩어져 있다(D문서 §규격어긋남 6건, `kl_parser/README` §7
> 9건, H문서 §7-⑥·§9 5건).
>
> **방침 전환(사용자 결정 2026-08-24):** 정답 샘플은 **예시일 뿐 정본이 아니다.**
> `break` item 이나 `h1~h4` 목록도 "이렇게 해라"가 아니라 "이런 것도 있다"였다.
> 그러니 **우리가 규격을 정하고, 그 결정을 농협에 통보·요구한다.**
>
> 이 문서가 그 정본이다. 흩어진 목록을 여기로 모으고, 각 항목을 **결정 / 요구**로
> 상태를 바꿨다. 아래 결정은 전부 코드에 이미 반영돼 있다(`kl_export.py`·`spec_check.py`).

## 1. 우리 규격 v1 — 결정 사항

### 1-1. `item` 유형

**결정: `text · table · image · h1 · h2 · h3 · h4` 7종만 쓴다.**

| 유형 | 우리 용법 | 근거 |
|---|---|---|
| `h1`~`h4` | 조문 제목 계층 (`제1장` → `제1조` → `1.` → `가.`) | 규정문서가 실제로 4단 계층이다 |
| `text` | 조문 본문 · 이미지 VLM 캡션 | |
| `table` | 표 (HTML 문자열) | |
| `image` | 추출 이미지 자산 | |

**`break` 는 쓰지 않는다.** 정답 샘플 1행에 있지만 규격서 목록에 없다. 우리 문서에
문단 구분을 별도 item 으로 낼 이유가 없다 — 청크 경계가 곧 구분이다.
**우리 검사기(`spec_check.py`)는 `break` 를 만나면 경고만 하고 통과시킨다** — 농협이
나중에 그걸 요구할 수 있으므로 실패로 만들지 않는다.

> **여기서 얻은 자유를 아직 쓰지 않았다.** item 유형을 늘릴 수 있게 됐지만 지금
> 필요한 게 없다. 필요가 생기면 §2-③ 의 좌표 문제가 첫 후보다.

### 1-2. `cust_meta` — 5칸까지만

**결정: `cust_attr1~4` + `cust_sattr1~3` 사용, `cust_sattr4~5` 는 비워 둔다.**

규격서 본문은 `cust_attr` 5개, 표는 10개다. **적은 쪽(5)에 맞춘다** — 6~10 이 실제로
저장되는지 확인되지 않았고, 5칸으로 충분하다.

| 칸 | 값 | 왜 이 칸인가 |
|---|---|---|
| `cust_attr1` | 청크 종류 (`text`/`table`/`image_caption`/`ocr_page`/`image_asset`) | 조회 전용. "원문인가 이미지에서 뽑은 것인가" |
| `cust_attr2` | `chunk_id` | 우리 산출물과 대조 (감사 추적) |
| `cust_attr3` | `asset_id` | 캡션 ↔ 원본 이미지 추적 |
| `cust_attr4` | `digital` \| `ocr` | **정본 신뢰도.** OCR 은 판독이라 틀릴 수 있다 |
| `cust_sattr1` | 출처 문서명 | 검색어 |
| `cust_sattr2` | 상품군 | 검색 필터. **파일명으로만** 정한다 — 본문 판단 안 함 |
| `cust_sattr3` | 조항 제목 | 검색어이자 출처 표시 |
| `cust_sattr4~5` | **비움** | 연결 키(`checklist_ref`) 자리로 예약 |

**`attr` 와 `sattr` 을 가르는 기준은 규격서에 있다** — `attr` 는 조회 전용,
`sattr` 은 **임베딩에 포함**된다. 그래서 좌표·ID 같은 값은 절대 `sattr` 에 넣지 않는다
(벡터에 섞여 검색 품질이 떨어진다).

### 1-3. `image` 의 크기·비율

**결정: `width`/`height` 는 mm, `ratio` 는 `"11%"` 같은 문자열.**

규격서는 "mm 기준"이라 하고, 정답 샘플은 PDF 는 pt, HWP 는 cm 로 보인다.
**규격서 본문을 따른다** — 단위를 명시한 유일한 문장이라서다. 우리는 pt·cm 를 mm 로
환산해 넣는다.

`ratio` 는 샘플이 문자열 `"11%"` 이므로 문자열로 낸다(규격서는 형식을 말하지 않는다).

### 1-4. `image` 의 `value`

**결정: 파일명만 넣는다.** 규격서가 "이미지 파일명"이라 했다. 정답 샘플에는
절대경로가 들어 있는데, **경로는 농협 서버의 것이라 우리가 알 수 없고 옮기면 깨진다.**

### 1-5. `page_info`

**결정: PDF 는 pt 실측값, HWP 는 빈 배열.**

규격서에 단위 명시가 없다. PDF 는 우리가 실제로 잴 수 있으므로 pt 로 넣는다.
HWP 는 사내 파서가 페이지 크기를 주지 않아 **모르는 값을 지어내지 않고 비운다.**

### 1-6. `parsed_status`

**결정: 성공 `"S"`, 실패 시 상태 파일에 `ERROR` + `message`.**
샘플에 `"S"` 만 있고 다른 값의 목록이 없다.

### 1-7. 청크 단위

**결정: 청크 = `item` 1:1.** 규격서에 명시가 없다. KL 이 `_hrc.jsonl` 의 각 행을
그대로 임베딩 단위로 쓴다고 가정한다.

### 1-8. 파싱 실패 응답

**결정: 파싱 오류 = `200` + `{"status":"ERROR","message":…}`, 그 외 오류 = `500`.**

규격서(`parser_howto.txt` §1-2)가 이렇게 나눈다. **농협 예제 코드는 둘 다 500 을 준다** —
규격서와 예제가 어긋난다. **규격서 본문을 따랐다.** 검사기(`boot_check.py`)가 이 분기를
실제로 태워서 확인한다.

### 1-9. 광고물은 `_hrc.jsonl` 로 내지 않는다

**결정: 광고물은 좌표·라벨이 살아 있는 통합 JSON 으로 낸다** (`_parsed.json`).
`POST /ad/parsing` 은 통신 방식만 규격과 같게 맞춘 **우리 자리**이고, KL 이 부르는
자리가 아니다.

이유는 규격 자체다 — `item` 에 좌표를 담을 칸이 없고 `cust_meta` 는 조회 전용
문자열이다. 광고 심의는 "이 지적의 근거가 원본 어디인가"를 화면에 찍어야 하므로
좌표가 본질이다. → 이 결정을 뒤집으려면 §2-③ 이 먼저 풀려야 한다.

## 2. 농협에 요구·확인할 것

### 요구 (우리가 정했으니 이렇게 받아 달라)

| # | 요구 | 왜 |
|---|---|---|
| ① | **`gunicorn` timeout 을 1800초 이상으로** | 예제 `gunicorn_config.py` 는 `timeout=180`. 우리 광고 파싱 실측 **627초**(`13. 대출성상품.pdf`), 대부분이 VLM 대기다. 180초면 시연 중에 일꾼이 죽는다 |
| ② | **파서 신고 `TIMEOUT` 을 1800초로** | 위와 같은 이유. 규격 기본값은 3시간이므로 1800 은 그보다 보수적이다 |
| ③ | **`item` 에 좌표 칸을 열어 주거나, `cust_attr` 를 좌표 용도로 써도 되는지** | 지금은 광고물이 KL 밖에 따로 있다(§1-9). 좌표를 담을 수 있으면 두 트랙을 한 창구로 합칠 수 있다. `cust_attr` 는 조회 전용이라 벡터를 오염시키지 않으므로 후보다 |
| ④ | **`cust_attr6~10` 이 실제로 저장되는지** | 규격서 본문 5 / 표 10. 우리는 5로 맞췄다. 10이 되면 좌표·역할을 더 담을 수 있다 |
| ⑤ | **`break` item 이 필요한지** | 우리는 안 쓴다. 필요하면 알려 달라 |

### 확인 (우리가 판단할 수 없는 것)

| # | 항목 | 지금 상태 |
|---|---|---|
| ⑥ | **KL 검색(조회) API 규격** | **자료 자체를 못 받았다.** 미구현 |
| ⑦ | PostgreSQL 접속 정보 · 버전 · 명명 규칙 | 미제공 ("내부 투입 시 제공"). 설계는 I문서에 굳혀 뒀다 |
| ⑧ | 라이브러리 버전 조합 | 농협 이미지 `fastapi 0.139.2` / 우리 시험 `0.115.6`. 그 조합에서 도는지는 농협 환경에서만 확인된다 |
| ⑨ | `gunicorn_config.py` 원본 | 농협 원본이 사내 모듈 `import dlp` 를 써서 우리 PC 에서 실행 불가. 방어 코드를 넣어 우리가 만들 수는 있다 |
| ⑩ | 폐쇄망 접속 · KL 슬롯 등록 | 미접속 |
| ⑪ | `image` 단위가 정말 mm 인지 | 샘플이 pt·cm 로 보인다. 우리는 규격서를 따랐다 |
| ⑫ | 보존 기간 · 삭제 정책 | 광고물은 심의 근거라 보존 의무가 있을 수 있다 |

## 3. 결정을 코드가 지키는지 어떻게 아나

결정을 문서에만 적으면 코드가 조용히 어긋난다. 그래서 **검사기 두 개**가 지킨다:

| 검사기 | 무엇을 확인 | 이 문서의 어느 조항 |
|---|---|---|
| `kl_parser/tests/spec_check.py` | `_hrc.jsonl` 이 규격을 지키나 (item 유형 · 파일명 · `cust_meta` 개수 · 표 HTML) | §1-1 · §1-2 · §1-5 · §1-6 · §1-7 |
| `kl_parser/tests/boot_check.py` | 농협 방식으로 기동되나 · 실패 응답이 200+ERROR 인가 | §1-8 |

`boot_check` 는 **일부러 되돌려 정말 잡는지 확인했다** — 되돌리면 NG, 고치면 OK.

§1-3·§1-4 (image 단위·value)는 검사기가 아직 안 본다 → 남은 일.

## 5. 아직 안 정한 것 (정직하게)

- **§2-③ 좌표 칸**을 농협이 열어 주면 §1-9(광고물을 KL 밖에 두는 결정)를 다시 봐야 한다.
  그때 두 트랙을 합칠지 말지는 지금 결정하지 않는다 — 답을 받은 뒤에 정한다.
- **변수형 템플릿 값 추출**(`"status": "미착수"`) — 광고 템플릿의 정형 문구는 완전일치로
  찾지만, 금액·기간처럼 값이 바뀌는 항목은 아직 값을 뽑지 않는다.
- **에이전트 분리 배포**는 규정문서 트랙만 코드가 있고 실행 이력이 없다. 광고 트랙은
  분리 모드 미구현.
