## 이 프로젝트가 무엇인가

농협은행 광고심의 자동화 PoC. 갈래가 **두 개**고 서로 다르다.

| | 규정문서 트랙 | 광고물 트랙 |
|---|---|---|
| 입력 | `nh-data/rag-data/` 의 규정·준수사항 문서 | `nh-data/new-sample-data/` 의 광고물(PDF/PNG/JPG/HWP) |
| 목적 | 농협 KL(벡터DB)에 색인되게 적재 | 매번 새로 들어오는 심의 대상 |
| 산출물 | `_hrc.jsonl` / `_hrc.json` (농협 규격) | 우리 `AdDocument` JSON (좌표·시인성 포함) |
| 좌표 | 불필요 | **필수** (심의 근거를 원본 위에 하이라이트해야 함) |

**현 파싱 파이프라인의 목표는 심의 판정이 아니다.** 광고 문구·표·디자인 문구까지
**모든 글자를 빠짐없이 구조에 맞게 뽑아 다음 단계(RAG/RDB 엔진)로 넘기는 것**이다.

### 1. 시인성 부착 (`813027a`, `5a13715`)
`Line.style` 에 글자 크기·굵기·색·글꼴을 담는다. 심의 항목 `DEP-FMT-01`/`LOAN-FMT-01`
("글자 색깔·크기가 혜택과 불이익을 균형 있게 전달하는가")이 텍스트만으로는 판정 불가라서.
- HWP 는 파서가 주는 `run_style.size_pt`(`declared`), PDF 는 글꼴칸 높이(`fontbox`).
  **두 값은 서로 다른 물리량이라 섞어 비교하면 안 된다** (`ir.SizeBasis` 주석).
- ⚠️ **`pypdfium2` 버전 함정**: `FPDFText_GetFontWeight` 가 5.12.0 은 실제 weight
  (260·360·440·520·600), 5.13.0 은 CSS 관례로 뭉갠 400/700 만 준다. 같은 글자가
  버전에 따라 굵음/보통이 갈렸다. 그래서 `text_style.is_bold` 는 **글꼴명을 1차 근거**로
  쓰고 굵기 원값은 `font_weight` 로 따로 담는다. 반입 패키지 목록에 버전 고정 필요.

### 2. 농협 KL Custom 파서 진입점 (`b43ff75`, `5a13715`)

폴링 → zip)을 지키는 얇은 창구. 농협 예제에서 **그대로 가져온 건 `app/service/status.py`
의 `DO NOT EDIT` 블록 43줄뿐**이고 나머지 921줄은 규격을 읽고 새로 썼다.
- 왕복 시험 2건 통과: 규정문서 HWP(4초) / 광고 PDF(90초, VPN 실호출)
- `POST /ad/parsing` 이 광고물용. 산출물은 `<파일명>_parsed.json` + `ad_summary.json`

3. **QR 라벨 두 개가 한 줄** (`상품가입바로가기이벤트바로가기`) + 표 영역에 잘못 포함.

4. **이미지 글자 OCR 오독**: 히어로 헤드라인이 `NH모두특래블리` (트→특).

   `기타자세한내용은해당상품약관…` 이 된다. TEXT 런에는 공백이 살아 있으니 살릴 수 있지만

## 환경 — 실수하기 쉬운 것들

- **파이썬은 반드시 `.venv/Scripts/python.exe`** 로 부른다. `python` 은 PATH 에 없다.
- `kl_parser` 는 **별도 venv** (`kl_parser/.venv-entry/`). 여기 `pypdfium2` 버전이
  메인과 달라서 위의 굵기 함정이 터졌다.
- **VPN 필요**. 확인: `GEMMA_URL` 에 모델 `['spark-gemma-4-26b-NVFP4-MTP',
  'b200-gemma-4-26b-NVFP4-MTP']` 가 보이면 살아 있다. 모델명이 옛 이름이면 전 호출이
  400 인데 러너는 exit 0 을 낸다.
- 셸은 PowerShell 이 기본이고 Bash 도 있다. **PowerShell here-string(`@'...'@`) 을
  bash 에서 쓰면 안 된다** (커밋 제목에 `@` 가 박힌 사고 있었음).
- 서버 재시작 시 `pkill` 은 Windows 에서 안 먹는다.
  `netstat -ano | grep :9101` → `taskkill //PID <pid> //F`
- **`nh-data/`, `prototype/`, `docs/etc/`, `kl_parser/samples/` 는 gitignore 대상**
  (농협 실제 광고물·규정 원문). 커밋 전에
  `git diff --cached --name-only | grep -iE "\.(hwp|pdf|png|jpg)$"` 로 확인해라.

## 내가 일하는 방식 (지켜줘)

- **문서보다 코드를 믿어라.** 주석·문서가 실제 동작과 다른 경우가 여러 번 있었다.
- **원본으로 검증해라.** JSON 만 보고 판단하지 말고 원본 이미지를 렌더해서 육안 대조까지.
  전에 외부 LLM 이 환각으로 지적한 걸 내가 그대로 옮긴 적이 있다.
- **과적합 휴리스틱 금지.** 판단 주체는 VLM 이고 regex·임계값은 폴백/보조 신호만.
  임계값을 새로 도입하려면 왜 그 값인지 실측 근거를 대고, 안 되면 구조적 해법을 찾아라.
- **착수 전에 완료 기준을 숫자로 못박아라.** 안 할 것도 명시해라.
- **원인을 추측하지 말고 계측해라.**
- **실행 결과에 정적 근거(조문 텍스트)를 복사해 넣지 마라.** 실행 결과엔 `field_key` 만.
- **삭제·되돌리기는 승인 없이 하지 마라.**
- 설명할 때는 흐름·로직 중심으로. 문법 설명은 최소, 자바 비유는 쓰지 마라.
- 지표는 **2층으로** 보고해라: 정본(결정론·100% 재현)과 VLM 층(매번 흔들림)을 갈라서.
